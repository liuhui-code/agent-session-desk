# Windows 工作台单实例

开发版对同一用户、同一 Windows 登录会话和同一数据作用域只保留一个工作台。普通启动会创建专属 Windows Terminal 窗口；再次启动只尝试恢复原窗口，包括最小化窗口，不新建第二只猫，不重启原 Run。

作用域包括后端种类、runtime／namespace 位置及 metadata 文件位置。不同作用域可以分别打开；改变 `--pet`、编辑器或模板参数不会产生第二个实例，也不会修改已经运行的实例配置。独立 `start`、`list`、`send` 等管理命令继续按原接口工作。

如果 Windows 拒绝前台切换，启动器提示手动切回原窗口。它不会制造热键、发送输入或自动重试；超时和无法确认状态也不允许另建工作台。窗口绑定已经改变时同样拒绝唤起。

退出工作台释放实例，后台 Run 仍由原终端后端持有；重新打开连接原 Run。UI 异常退出后，系统释放实例 mutex；Terminal 可能留下错误页，错误页不是仍在线的工作台。进程存活、终端存活和 Agent 就绪仍分别判断。

首次从旧版本升级，请先正常退出旧工作台，再运行新构建；旧版本不参与本协议，程序不会自动关闭或接管它。额外原生 Terminal Tab 的精确选择、混合权限、多用户、多屏和完整资源／发布接受仍开放。

共用同一 Terminal 进程的两个窗口、五路首次并发、重复启动、点猫定位及正常／受控 UI 崩溃后原 Run 与草稿保持，已有该本机组合的有界验证。

实现决定见 [ADR-0055](adr/0055-scoped-workbench-instance-and-owned-window.md)，实际执行及失败记录见[专项报告](testing/results/2026-11-26-workbench-instance.md)。此变更不引入 M3 常驻 Host，也不提供后台持续提醒。

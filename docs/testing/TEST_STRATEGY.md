# 测试策略

日期：2026-11-21。状态：测试设计基线，产品测试未执行。

测试从 [Feature Ledger](../FEATURE_LEDGER.md) 的验收条件出发，验证可观察行为与关键不变量。实现类名、函数拆分或数据库驱动改变时，这些行为要求应继续成立；测试不照抄实现分支来证明实现自身。

## 1. 最重要的失败模式

| 风险 | 必须保持的不变量 | 对应能力 |
| --- | --- | --- |
| 指令发错会话 | 消息绑定稳定 Session 和指定 Run，排序/重命名/重启不改变目标 | FL-005、008、013 |
| 状态夸大 | 持久化、终端写入、agent 接收、完成、用户验收分别有证据 | FL-008、009、014 |
| 崩溃后重复执行 | 无法证明未写入的尝试保持不确定，不自动重放 | FL-013 |
| 输入交错 | 多发送者串行，attach 用户占用时默认暂缓自动投递 | FL-002、008、009、012 |
| 关闭界面丢任务 | TUI/attach 客户端退出与 agent Run 生命周期分别判断 | FL-006、011 |
| 历史失真 | 屏幕、日志、结构化消息和模型上下文区分，缺口显式 | FL-007 |
| 资源长期增长 | 预览、内存、消息和日志有界，后台进程成本完整计量 | FL-015 |
| Windows 纸面支持 | 原生环境实际验证输入法、路径、终端交接与生命周期 | FL-016、017 |
| 误改用户环境 | 产品 namespace、配置、测试目录和进程归属明确 | FL-001、006、013 |

更细的时序见[状态与竞争矩阵](STATE_AND_RACE_MATRIX.md)。本库包含功能、边界、异常、并发、恢复、兼容、易用性、稳定性、性能、控制边界、发布、属性与模糊测试；一个用例可有多种标签。

## 2. 优先级与测试层次

P0 表示适用阶段的关键风险：错目标、已确认记录丢失、未知结果自动重放、关键原生路径不可用等。P1 为正常产品能力与重要边界。P2 为扩展压力、较低风险组合或后置功能。**优先级不等于每次提交的执行频率**；长稳 P0 也不应塞入每个小改动的快速检查。

| 层次 | 适用内容 | 能证明的范围 |
| --- | --- | --- |
| unit | ID、消息规则、游标、边界值、纯状态规则 | 模型行为；不能证明 ConPTY 或 Windows 输入 |
| contract | 后端命令、响应解析、输入传输、CLI 错误语义 | 适配器与外部接口边界 |
| integration | SQLite、队列、多个调用者、故障屏障与恢复 | 真实组件协作；标明是否使用模拟后端 |
| windows_e2e | 真实 psmux、Windows Terminal、shell 与 agent | 该环境组合的原生行为 |
| manual | IME、焦点体验、视觉评审、诊断与材料审核 | 记录操作与证据；人工评审不伪装自动断言 |
| soak | 小时级负载、反复重连/故障与资源趋势 | 特定负载和时长内的稳定性 |
| release | 干净安装、升级、回退、依赖与整条用户流程 | 对应发布物的可交付性 |

每个用例的 `level` 是建议的主要验证层；需要多个层次时保留关联证据，不能用 unit 结果替代原生用例。

## 3. 用例状态

- `status=designed`：测试描述已经建立。
- `spec_state=ready`：依据足够，预期可明确；不表示夹具或软件可运行。
- `spec_state=needs_decision`：有容量/策略/接口等未决项。可以采集基线，但在相关规则固定前不能把整个用例判通过。
- `spec_state=deferred`：依赖明确后置能力，当前发布范围不执行。
- `execution=not_run`：本库当前统一状态。后续真实执行结果保存在报告中，关联源码、环境和用例版本。

报告结果使用 `pass / fail / blocked / not_run / not_applicable`。`blocked` 必须有原因；`not_applicable` 必须说明范围依据，不能拿来隐藏失败。复跑通过时仍保留首次失败与修复证据。

## 4. 分阶段执行

| 阶段 | 先做什么 | 阶段结束需要什么 |
| --- | --- | --- |
| 本轮 | 完成用例设计、引用校验、风险矩阵 | 资料一致；不产生产品通过率 |
| M0 | FX-ECHO/FX-VT/FX-PROCESS，最小启动与 attach，v2 迁入，原生输入，资源基线 | 原生关键路径与已选后台合同通过；关闭影响本阶段的未决项 |
| M1 | 单 Session/Run、配置、基本存储、停止/异常、焦点 | 对应 P0/P1 有真实结果，不能只展示正常流程 |
| M2 | 多会话身份、独立后台、重连、日志缺口、有界缓存 | 原 Run 可核对，错目标与泄漏类风险得到证据 |
| M3 | FX-READY 与故障屏障、读取/消息/Host/CLI/回复 | 正常投递和不确定恢复都通过，UI 关闭后的消费有独立验证 |
| M4 | 干净发布环境、完整回归、8 小时基础长稳、安装/升级/回退与说明 | 适用 P0/P1 无未解释失败；预算、兼容矩阵与限制明确 |

长稳采用 8 小时基础轮次、24 小时扩展轮次作为**测试工作量设计**，不是产品保证。扩展轮次按变更风险安排。预算不明的用例先做测量，预算确定后才能判断达标。

## 5. 边界值与组合

对已确定上限 B，至少覆盖 0、1、B−1、B、B+1，以及适当的远超上限值；单位明确是字节、字符、条目还是屏幕 cell。非法负数、溢出与截断路径只在其输入接口实际可接收时注入。不得凭空设定产品未承诺的长度或性能阈值。

字符串覆盖空值、空白、中文、组合字符、emoji、引号、末尾反斜杠、换行和控制字节。模式覆盖直接 executable 与显式 shell；环境覆盖 Windows 路径、终端、IME 与能力组合。详细矩阵见 [ENVIRONMENTS.md](ENVIRONMENTS.md)。

并发以明确屏障控制事件次序；随机调度作为补充，保存种子。缩减失败轨迹为可复现的最短场景，再增加回归用例。显示帧允许按设计合并，指令、状态证据和控制事件不因绘制优化丢失。

## 6. 稳定性与性能结论

记录 0/1/5/10 会话、空闲/当前输出/全部输出，固定窗口、负载、日志策略及预热配置。分别计量 TUI/Host、psmux server/client、shell/控制台、agent，提供直接运行同样 agent 的对照。

连续采样后查看稳定区间、峰值、趋势与结束后的回落；不能只用首尾两点、截图或一次 GC 证明无泄漏。CPU 采样口径、工作集中的共享页、私有提交与系统总量分别说明。测试采集器本身的开销单列。

预算配置见 [BUDGETS_AND_DECISIONS.md](BUDGETS_AND_DECISIONS.md)。没有实际结果时，保持“未测量”；没有接受的预算时，保持“基线待判定”。

## 7. 证据与维护

测试输入全用可公开的假数据。故障只施加在隔离目录、测试进程、专用 VM 或有限容量测试盘。测试结束按测试标记回收，不能按同名进程批量误杀用户任务。

每次运行使用[执行报告模板](templates/EXECUTION_REPORT.md)，长稳附[资源报告](templates/PERFORMANCE_REPORT.md)。用例变更与实现提交一同评审，FR/FL 编号稳定。重大预期变化先更新需求或 ADR，再改用例。新增测试案例不提高 Feature Ledger 的功能状态。

# 测试环境与兼容矩阵

设计日期：2026-11-21。**以下均为计划环境，目前没有产品测试执行结果，也没有 Windows 兼容通过记录。** 用例引用这些 ID；实际执行时必须保存完整 manifest，不能只写“Windows 测过”。

测试范围由 [Feature Ledger](../FEATURE_LEDGER.md)、[ADR](../adr/README.md)及[用例目录](cases/)确定。数值限额与待决行为见 [BUDGETS_AND_DECISIONS.md](BUDGETS_AND_DECISIONS.md)；环境清单不扩展当前产品支持承诺。

## 环境定义

### ENV-UNIT

用于纯逻辑、状态机、输入合同及可控假后端测试，可在开发机或 CI 上执行。冻结随机种子和时钟，记录 Go/测试工具链、fixture 和产品提交；用例需要磁盘时使用独立临时目录。

Linux 上的逻辑测试、交叉编译和模拟终端只证明对应逻辑或构建路径。它们不能证明 ConPTY、真实 IME、Windows 进程生命周期、字体渲染或 attach 恢复正常，也不能代替下面的 Windows 环境。

### ENV-WIN-BASE

首轮计划采用 **原生 Windows 11 x64 + Windows Terminal + 明确版本的 PowerShell**。记录实际 Windows build、终端版本、PowerShell 具体版本/发行类型及 psmux 正式二进制身份；不使用笼统的“最新版”作为复现依据。

该环境不安装或启用 WSL，不依赖 Unix shell、tmux 或开发机额外 PATH/隐藏配置。应用与 fixture 使用原生 Windows 进程；允许 Windows 虚拟机，但必须记录虚拟化信息，资源数据不能直接推广为所有物理机结果。

这是首轮验证基线，**不等于最低 Windows 版本已经确定**。首次使用的真实 agent 及命令按 O-006 固定；确定性 fixture 与真实 agent 的结果分别记录。

### ENV-WIN-COMPAT

用于基线外的兼容组合及最终发布复验。先按实际风险选择组合，再用 pairwise 补充参数交互；保留组合清单及未覆盖项，不默认执行完整笛卡尔积。

ARM64、旧 Windows build、Windows 10、其他终端和未选定 shell 均为待验证项；只有决定纳入支持矩阵后才成为对应版本门槛。未经测试的组合不能从同类结果推定支持。

### ENV-UNIX-LATER

供后续 macOS/Linux 与 tmux 适配使用，记录 OS、架构、终端、shell 和 tmux 版本。当前属于后续范围，不构成 Windows 首版的默认发布门槛；Unix 成功也不替代原生 Windows 结果。

## 矩阵轴与强制组合

| 轴 | 至少记录的取值或维度 |
| --- | --- |
| 系统与架构 | 精确 OS build、x64/拟支持架构、实体机/虚拟机、CPU/RAM/磁盘信息 |
| 启动入口 | 原生 .exe；拟支持的 pwsh/Windows PowerShell、cmd、.ps1/.cmd/.bat、显式 shell 模式；不支持项明确列出 |
| 终端显示 | Windows Terminal 版本、行列数、字体及回退、DPI/缩放；正常与窄窗口 |
| 文本与输入法 | ASCII、中文、宽字符、组合字符、emoji；IME 版本、预编辑/确认/取消、切换键 |
| 路径与区域 | 空格、中文、引号/反斜杠参数；用户/数据目录；语言环境和相关编码设置 |
| Agent 能力 | 通用未知状态 CLI、合作 ready/busy fixture、可控退出 fixture、至少一个实际目标 agent |
| 会话与负载 | 0/1/5/10 会话；空闲、单会话持续输出、所有会话持续输出、快速切换与 attach |

下表为必须保留的风险组合；pairwise 不能将其删除。阶段尚无相应实现时记为未执行/阻塞，不伪记通过。

| 阶段 | 强制组合与目标 |
| --- | --- |
| M0 | ENV-WIN-BASE 无 WSL；原生 exe + 含空格/中文路径 + 参数引号；验证真实 argv/cwd/env 与启动错误 |
| M0 | 基线终端 + 中文 IME + CJK/组合字符 + 多行粘贴；分别覆盖管理表单和 attach 的输入与提交 |
| M0 | 全屏 VT 目标 + resize + attach/detach；覆盖正常返回、attach 客户端异常退出、目标提前退出 |
| M0/M2 | 0/1/5/10 会话的空闲及输出负载；关闭产品预热，采集完整进程归属和缓存增长 |
| M2 | 两个不同 Run + 快速切换 + 迟到预览；用户自己的独立后台会话同时存在，验证不串输入、不误清理 |
| M3 | generic unknown 与可靠 ready/busy 各一组；UI 关闭/Host 存活、无消费者、attach 占用输入、目标 Run 变化 |
| M4 | 每个正式声明支持的系统/架构组合运行发布冒烟；对最低支持组合和已知高风险组合复跑相关完整核心用例 |

## 每次执行的环境 manifest

- 身份：run ID、用例 ID、日期/时区、执行人、产品 commit/构建模式/包哈希、配置 schema 与配置摘要。
- 平台：Windows build、CPU 架构与型号、内存、磁盘类型/可用空间、虚拟化方式、相关资源限制。
- 终端：终端与 shell 的实际版本、启动入口、行列、字体/回退、DPI、IME/快捷键、语言与编码设置。
- 依赖：Go 与 Charm 锁定版本；psmux 来源/tag/commit/二进制 SHA-256；数据库/解析器版本及适用配置。
- 对象：agent/fixture 版本、脱敏后的 executable/args/cwd/env 差异、Session/Run 映射、能力声明、初始状态。
- 负载与观察：随机种子、文本样本哈希、输出速率/会话数、时间与采样间隔、故障点、监控工具版本、预热/稳定窗口、结果与证据位置。

没有固定的 manifest 字段记为“未知/未记录”，不能以推测补齐；若缺项影响复现或断言，则该执行结果为阻塞或证据不足。发布证据只包含合成内容及脱敏后的必要信息。

## 隔离与故障注入

每轮使用唯一测试运行 ID、临时数据目录、独立 psmux namespace（-L）及配置（-f），并设置产品专用 PSMUX_DATA_DIR。按已接受策略使用 PSMUX_NO_WARM=1 与专用配置中的 warm off；同时检查真实进程树，不凭配置文本判断预热已经关闭。

凭据仅用可识别的假值，例如 ASD_FAKE_SECRET；测试账户、数据文件与工作目录均为合成对象。不能沿用用户真实项目、会话内容或模型密钥作为测试样本。

注入终止或清理前核对 **PID + 创建时间 + 本轮 namespace/数据目录 + Session/Run 归属**。禁止按进程名批量结束 psmux、shell 或 agent；保存初始用户会话清单，清理后确认无关对象仍存活。单凭 PID 不能应对 PID 被复用的情况。

磁盘满、权限变化、数据库破坏、系统时间跳变、睡眠/重启等试验限可回滚 VM、专用临时卷或明确隔离对象；先建立快照/恢复步骤，不填满系统盘或改变用户全局配置。记录故障触发、恢复、残留对象和证据；清理失败时保留归属信息供后续处理。

## 资源采样口径

分别记录 TUI/管理 CLI、可选共享 Host、psmux server/client、shell/ConPTY 辅助进程、agent，以及外层 Windows Terminal 的归属。共享终端宿主单独列出；无法分摊时说明，不能悄悄漏算或重复算为产品独占成本。

至少采集进程数、工作集、Private Bytes、CPU、句柄/线程、磁盘与日志占用、缓存/队列规模及操作响应时间。工作集求和可能重复计算共享页，不能直接叫作物理内存总占用；按相同环境、尺寸与负载和直接运行同一 agent 的基线比较。

使用单调时间记录间隔，保留原始采样及 warm-up/稳定窗口；不要由单个瞬时样本断言泄漏。持续负载须检查稳定区间趋势、停止负载后的回收以及进程退出后的残留，数值门槛以预算文档中已批准值为准。

稳定性用例中的 **8 小时等时长是测试设计的观察窗口，不是产品可用时长或性能承诺**。没有预算时可以采集基线，不能把未知预算自动判为达标；没有完整执行窗口时如实记录未执行、提前终止或失败。

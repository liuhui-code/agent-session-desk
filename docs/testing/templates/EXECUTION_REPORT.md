# 执行报告模板

> 模板，不是已经执行的报告。复制到 `docs/testing/results/<测试批次>/report.md` 后填写；未运行项保持 not_run。

## 本次执行

| 字段 | 记录 |
| --- | --- |
| test_run_id / 日期与时区 | 待填写 |
| 执行人/执行入口 | 待填写 |
| 产品 commit / 包哈希 | 待填写 |
| 用例库 commit / 选中 ID 与参数 | 待填写 |
| Windows build / 架构 / 终端 / shell | 待填写 |
| 字体 / DPI / IME / locale | 待填写 |
| Go / Charm / psmux / 存储与适配器版本 | 待填写 |
| 实际 agent / 夹具 commit / 种子 | 待填写 |
| 配置 / 预算 / namespace / 脱敏数据清单 | 待填写 |
| 前提或未决项是否已经关闭 | 待填写 |

## 结果

| Case ID / 参数组合 | 结果 | 实际观察与断言 | 证据 | 缺陷/阻塞原因 |
| --- | --- | --- | --- | --- |
| 待填写 | not_run | 未执行 | 未提供 | 待填写 |

结果仅可使用 pass、fail、blocked、not_run、not_applicable。每条 pass 必须有实际运行与预期对照；not_applicable 要有范围依据。参数化组合分别记录，不以一个组合通过覆盖全部变体。

## 故障与复现

填写最短步骤、屏障与调度、目标 Session/Run/message_id、预期与实际、原始输入/回执证据。记录首次失败和复跑，不删除不稳定或失败轮次。报告中不放真实密钥或私人会话内容。

## 环境结束检查

核对测试进程与目录；按测试标记清理。说明仍存活 Run、unknown 请求、保留证据和未执行的清理动作。不要按同名进程批量终止用户任务。

## 结论与台账

说明此次结果适用的版本和环境，仍未覆盖的组合与未决规则；链接受影响的 FR/FL、缺陷和修复提交。只有对应能力全部适用验收通过后才更新 Feature Ledger，不由单条用例或一次截图推定整项完成。

## 边界取值与结果判定

- 容量上限使用 B-1、B、B+1；最小尺寸也增加 B+1，明确哪侧属于支持范围。零、空、负数/溢出等非法输入另组测试，不能混入合法往返断言。
- 多字节样本先按固定编码计算真实字节数，用 ASCII 填充等方式精确到达边界；不要在半个 Unicode 字符处切断来假装得到有效正文。
- 等待/TTL 比较要固定时钟和等号规则；P95 是统计预算，需固定观察窗口及测量起止事件，不能把单个耗时样本当 P95。
- 确定性容量条件按已定范围接受/拒绝；已确认记录不能因超限被静默丢弃。回执强度、目标身份和不确定结果的断言始终保留。
- 未赋值或合同未定时，可采集基线；需要该值的通过判定必须记录 blocked / 证据不足，不能将 null 当作无限大、0 或自动通过。
- 用例中的 8 小时、100 轮、10000 条等是设计负载/观察窗口，不是产品 SLA。执行时保存实际完成范围，提前结束不能记为完整稳定性通过。

## 关闭方式与变更范围

1. 实施对应能力前，维护者结合可运行切片、实际 Windows 结果、产品行为与资源基线，写清合同或预算；必要的产品取舍在该阶段讨论。
2. 将具体规则、数值、单位、作用域、版本和依据记录到实现/配置规范，并更新 registry 与本页对应条目/预算表；已关闭的 TBD 改为 resolved 并提供 resolution 引用。选择不支持或不启用也是明确结论，不能只删除测试。
3. 精化待决实现细节可更新现有说明；改变已经接受的核心架构或产品范围时创建后续 ADR，并同步 FR/FL 与路线图。
4. 把依赖该项的用例改成精确可判断的预期，再将 spec_state 从 needs_decision 调整为 ready；这一步仍不改变 execution 为通过。
5. 在对应环境真实执行，保存环境 manifest、输入、状态/进程/资源证据与失败样本。发布前复验支持范围，不能把一个组合的结果推广到未测组合。
6. 预算或合同变化应找出全部引用用例并重新生成索引、执行受影响回归；保留旧版本依据，使过去的通过结论可解释。

# 原生复制模式鼠标手势的本地验证

日期：2026-11-24；基线 `9d6cb1c`。按 [ADR-0029](../../adr/0029-native-copy-pointer-gestures.md) 推进 U18，继续还原终端选择交互。**仅原生复制模式的无修饰左键切片；Windows、实体鼠标和系统剪贴板未执行。**

## 当前行为与边界

管理 `v` 或已有滚轮入口进入后端复制模式后，在已聚焦的活动终端内容内按左键、拖动及释放，经既有有界 FIFO 发往原 pane。零基内容坐标排除产品框、Tab 和页脚；`pane-mouse` 的左按／拖／释放为 `0 M`／`32 M`／`0 m`，每次随后 `dump-state`。不转换为文字、方向键或 Enter；原生后端拥有选区、光标、边缘滚动和释放复制语义，复制事件继续走单 OSC52 通道。

管理焦点的第一次点击只聚焦；原生搜索提示编辑中、普通实时程序、其他按钮及修饰组合不启动此手势。已开始的拖动越过 Tab／侧栏／分隔符仍归原手势，不变成管理动作；每个 UI 最多一个手势，重复按下／释放不重复提交。边缘坐标允许一屏最大范围内的有符号值，越过防御界限取消，不夹到别的控件。

切 Tab、键盘、粘贴、滚轮、resize、进入模态、断开、模式退出、提示编辑或后端尺寸变化取消本地手势。尺寸恢复也不续接旧手势；无按钮运动不冒充释放。不合成释放／复制、不重试、不跨 Run 重放；已接受的指针仍在原 FIFO 排空，后端未完成选区可能保留，可由用户 Esc 取消。输入队列满或不可用时清除本地手势并沿现有输入错误提示处理。

CopyMode 帧是观察，不是模式锁；后端按收到时的模式解释，外部客户端可能在两者之间改模式。不能据模型声明鼠标永远不会到达子程序，也不能从传输成功推断选区或剪贴板成功。正常终端直接拖选、目标程序鼠标、修饰键／其他按钮、边缘驻留定时滚动和最后绘制选区与复制端点一致性仍开放。

没有增加依赖、存储版本、历史副本、服务或样式数值；原 terminal input 和原生历史所有权不变。Unix tmux 路径未新增此能力。

## 实际本地证据

- 首条终端 RED：原连接无指针能力。实现后，真实 `net.Pipe` 流验证原 pane 7 的按下／拖动／释放顺序、精确协议与刷新，无键盘输入。第二个流合同验证动作注入字符串、空动作和坐标上限拒绝，合法有符号边缘仍可写；拒绝事件不污染后续流。这不是原生 psmux 执行。
- UI RED：原点击／运动／释放没有原生选择动作。实现后，五个顶层／含子测试共 22 个模型服务测试覆盖内容坐标与顺序、跨边缘归属、重复事件、原 FIFO 排空后切 Tab、新 Run 独立文字输入、十类取消，以及七类非启动状态。合成连接记录输入，没有真实鼠标或剪贴板调用。
- 首次生命周期测试误用不存在的测试夹具字段而编译失败，修正为既有 viewID；错误日志单列，不算产品行为 RED。
- 尺寸 RED：原屏幕尺寸改变后释放仍发出；绑定实际屏幕尺寸后，追加“变小再恢复”又复现旧手势续接。改为首次失效帧即清除后，两类回归通过。此前完整检查通过的旧结果保留，最终检查在修复后重新执行。
- 最终 `go test ./...`、`go test -race ./...`、`go vet ./...`、`go mod verify`、500 物理行检查及测试目录校验通过；Windows amd64 的 terminal／UI 测试与产品只作交叉构建，不计原生执行。339 项设计用例保持 designed/not_run。

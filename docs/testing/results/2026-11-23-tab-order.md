# Tab 排序与原终端身份实测

日期：2026-11-23（上海时间；回执为 UTC）。基础提交 `02f3702`；包含本报告的 Git 提交绑定最终代码与证据。本轮是 ADR-0014/0016 的局部实现，不代表完整上游视觉、真实 agent 或发布验收。

## 行为

左键拖动 Tab 标题到可见 Tab 的位置可排序；管理焦点 `[`／`]` 将活动 Tab 左／右移动一位，边缘不循环。终端焦点的同名字符继续发给原程序。帮助页已说明入口。

排序只移动带完整 View ID／Session／Run 的视图项，并按原活动 View ID 找回活动位置。它不重连、不重启、不写终端，也不改变管理列表的顺序。输入排空期间的 switchTarget 继续按 View ID 解析，不能因数组位置变化把输入发给另一个 Run。

鼠标手势记录开始时的可见槽位，避免长短标题交换后位置变动导致静止指针下反复跳回。释放、离开 Tab 行、失去左键、键盘／粘贴／滚轮、resize 或断开结束手势；已完成的移动保留。新建／关闭按钮不启动拖动。

顺序仅当前 UI 内存有效，不写配置／数据库；鼠标不自动滚向隐藏 Tab。可先切换到目标 Tab，再在管理焦点用键盘移动。此为产品 Tab 导航实现，固定 Agent Deck 没有相同 Tab 栏，不新增来源或生产依赖；既有派生鼠标路由与帮助沿用原许可。

## 剩余范围

顺序持久化、鼠标越过可见范围自动滚动、跨窗口移动不在本切片；现有键盘路径可管理不可见的活动 Tab。当前原生流程只覆盖两个可见 Tab，更多数量与窄窗排序仍需原生扩展。阻塞写入／切换竞争与取消矩阵是模型证据，不能提升为所有 Windows 调度／输入设备组合通过。

完整选择／复制／搜索、目标 TUI 鼠标、真实 agent、其他 shell／IME／后端、完整上游视觉接受、资源预算和长稳仍开放。本轮不重测资源，也不以排序测试提高 FL-003/004/012/018 的整条能力或发布状态。

# 2026-11-23：创建对账、空工作区与断开只读

结论：修复创建与后台发现的两种时序问题，统一空工作区／失败视图的管理焦点，并在连接失败后保留上次已观察屏幕供只读检查。基础提交 `a2cefd6`；对应 ADR-0016 和 FL-001/003/005/006/018。没有新依赖、常驻进程、输出文件或会话恢复协议。

## 行为与 TDD

- 旧 List 在 Start 成功后到达，曾将刚创建的 Run 判为缺失并断开。成功结果现在递增发现代次并取消旧请求，迟到结果不再覆盖新状态。
- 首个 Run 被发现后、Start 结果才返回，曾生成两个同 Run Tab。现在按完整 Session ID／Run ID 对账列表和已有视图，不重复插入或重连，不合并不同 Run。
- 鼠标关闭最后一个 Tab 后，内部焦点与状态提示曾仍表现为终端模式。现在回到管理模式；确认空列表后同样如此，F6 不会把焦点交给不存在的终端。
- 失败时取消连接／待写状态，清除未发送缓冲并回管理焦点，不重放输入。已有上次观察屏幕继续以只读方式显示，隐藏真实光标，F6 不重新授予输入权限；用户显式 r 才重查。没有观察过屏幕时仍显示错误。

RED-01 至 RED-05 和最终 GREEN 见[证据](2026-11-23-workspace-reconciliation-evidence/)。中间 `green-02.log`、`green-03.log`、`green-03-final.log` 仍失败，不能据文件名算通过；有效复验为 `green-02-final.log`、`green-03-verified.log`、`green-04.log`、`green-05-all.log` 和最终全量检查。关闭焦点测试同时核对内部输入归属、真实光标与可见管理状态，避免只改提示文案。

两个发现时序用可控模型服务确定复现；它们不是实际后端延迟注入测试。完整普通／race／vet／模块／500 行及 catalog 检查通过；339 个 catalog 仍 designed/not_run。

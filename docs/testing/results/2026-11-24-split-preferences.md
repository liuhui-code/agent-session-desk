## 结果与范围

管理 `<`／`>` 每次调整 5%，沿既有 tokens 夹取 10%–90%，显式选择写入元数据目录的独立 `ui.toml v4`；`sidebar_percent=0` 表示自动，10–90 表示手动列表占比。`=` 保存自动，管理／终端焦点使用原 35%／18%。手动值跨焦点及重新加载保留，沿现有宽双栏／上下布局和最小面板约束绘制。

拖动时只预览并发送现有终端尺寸事件；拖动结束一次接受最后预览。松开不依赖按钮或坐标，无按钮移动、新点击／滚轮等漏松开收尾沿固定来源；主动键盘／缩放／切视图也收尾。纯启动、焦点、缩放、悬停、单击或已经在边界的无效调节不制造保存。非用户连接失败／外部关闭不发起新保存。

比例与密度、模式、默认及自定义组折叠共用一个串行整份偏好写入器。运动预览与已接受快照分开，旧成功回执不会回退新选择或正在拖动的预览；失败恢复最后成功偏好，取消预览和等待退出，错误保持可见，不自动重试。退出继续等待已接受偏好及原终端写入。

v1–v3 只读加载时默认自动，不改写；显式修改才发布 v4，未知字段／版本、错误类型、越界值拒绝，保存失败不替换原文件。沿已有 16 KiB 防御读取、同目录临时文件验证及 rename 发布；多进程仍是最后成功替换者生效，非 CAS／断电耐久证明。SQLite v5、启动模板、依赖、design tokens 及 Run／Tab 身份不变。

## RED → GREEN 与产品检查

1. 配置 RED：原实现拒绝 v4。增加比例字段、严格版本／类型／范围校验和 v4 保存后通过。首次 GREEN 尝试使用无效 `default` 自定义折叠 ID，夹具纠正为真实格式后通过；这是测试准备错误，失败日志保留。
2. UI RED：比例键未触发持久保存；接入串行写入、CLI 载入与重开后通过。验证手动／自动、原 Run／草稿身份、运动中不落盘、松开一次保存、旧回执／其他偏好不覆盖预览以及退出等待。
3. 来源对照发现此前“中断即取消”的初稿会丢弃用户选择，且不能接受无按钮松开。对齐源码后，以七种结束路径先 RED 再 GREEN：键盘、点击、滚轮、无按钮移动、缩放、切 Tab 和无按钮松开；保存最后运动值，不使用松开坐标。
4. 故障 RED：回滚尺寸事件无法入队时覆盖了偏好错误。调整处理顺序后，原比例与“偏好未保存”都保留。验证保存失败取消等待退出且不自动重试。
5. 无效选择 RED：已经在自动／最小／最大比例时，按键可能顺带保存临时组展开。改为只有比例选择改变才接受整份保存，三种情形均 GREEN。
6. 配置边界覆盖 0、10、35、90；非法 -1、1、9、91、100、浮点、布尔、字符串、溢出及低版本携带新字段／未来版本，拒绝时原文件不变。v1／v2／v3 读取不改写、显式升级及无临时文件残留均通过。CLI 载入／保存／已取消上下文和启动配置哨兵另有集成测试。

最终 `go test ./...`、`go test -race ./...`、`go vet ./...`、`go mod verify`、生产源码 500 物理行检查均通过；后续无效选择修正后的日志、交叉构建哈希与修正前结果分开保留。测试目录校验通过，339 项仍 designed/not_run，216 ready／123 needs_decision；目录工具不执行产品测试。

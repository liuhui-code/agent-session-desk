# 验证前置与驱动失败

首次 Go 调用使用默认 HOME 构建缓存，被沙箱拒绝；初始“RED”因此不算行为失败。改用临时 GOCACHE 后，默认模块缓存不可写；一次替代缓存未包含 sqlite，受限网络下载失败。最终沿既有隔离缓存 ASD stability 路径执行，保留真正的缺方法／行为 RED 与 GREEN。

严格 JSON 初轮有两个用例未匹配多行示例，造成 null args／missing args 假失败；修正输入构造后，剩余 surrogate 拒绝的真实失败再修复。CLI 初轮测试误把 Run 的 int 返回当 error，编译失败；改用内部可返回 error 的入口后，捕获了未知 recovery-profile 命令的真实 RED。预约首轮测试命令快照和声明不一致，明确拒绝后修正测试快照。分别保留对应日志，不混为产品故障。

Windows 初始准备阶段出现日志解码错误，以及随后一次全新目录保护失败；原始准备 stdout 没有完整保留，不据此判定产品行为或零操作。r1 未用于接受，后续使用独立 r2/r3/r4/r5。r2 的相对示例文件缺失与模拟 env 使用保留前缀失败原样保留；r3 自包含后通过。r4 是去重复块及清理断言后的单独产品；最终 r5 是回执身份复核后的产品。旧轮结果不能作为最终字节的重复测试数。

公开 Windows 日志统一从 UTF-16 解码为 UTF-8，并将 C:\Users\用户名 替换为占位；只包含合成夹具及元数据测试。原始字节留在本机临时证据目录，不入库私有凭据、context、历史正文或测试数据库。

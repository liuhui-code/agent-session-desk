# 长表单字段、缩放与真实光标

日期：2026-11-24（Windows 原始 UTC 为 2026-11-23）。基线提交 `adba85d`，关联 FR-01/03/11、FL-001/003/012/016/018/019、ADR-0014/0016，以及差异清单 U03/U08/U11/U12。本轮为局部实现／复验；没有整体视觉接受或发布结论。

## 问题与修改

固定 Bubbles 2.2.2 的 `SetWidth` 只赋值，不重新计算输入横向可见窗口。旧测试只检查光标位于整个终端内，长字段缩窄后仍可能显示旧开头，光标落在裁剪位置。新建还少预留一格末端真实光标。

`input_view.go` 增加共享尺寸重算：按字段总宽扣除 prompt 和一格光标，重算窗口后恢复原 Value／Position；新建四字段、会话与组改名、分组名称／默认目录、搜索统一使用。焦点、业务验证、输入归属、依赖、SQLite／ui.toml 和 design tokens 不变。

同一 keycap `1️⃣` 在锁定的 uniseg 中为一格，产品 x/ansi 中为两格。只对含 keycap 的非空字段增加整 grapheme 显示投影，文字与真实光标共用计算，颜色仍取组件的 token 样式；不修改字段值，不把组件的 rune 插入位置静默吸到 grapheme 起点。普通文本仍使用原组件视图，空占位仍只剔除此前确认的组件生成 NUL。组件编辑模型仍按 rune 工作，本轮没有承诺 grapheme 原子删除或所有复杂文字编辑。

Context7 解析到官方 `/charmbracelet/bubbles/v2.0.0`，它支持 v2 尺寸 setter 和真实光标 API 的一般说明，**不是 2.2.2 专属索引**。具体赋值／overflow／Cursor 行为另外核对本机精确锁定的 2.2.2 源码哈希。来源与许可不变，未升级依赖，也未新增上游组件一致性帧或声称中文布局与来源完全一致。

## TDD 与模型证据

- 9 个字段 × ASCII／中文、组合音标、ZWJ emoji、keycap × 末尾／中部，共 36 组。每组以 120×32、63×25、49×25、27×12、120×12、49×12、120×32 往返，检查完整值、逻辑插入位置、真实光标与唯一标记的单元格位置、精确帧尺寸，最后在原位置插入 `!`。共 252 个模型尺寸状态。
- 用最终修正后的这 36 组测试配合基线五个生产文件 overlay，RED 为 35 个子测试失败、1 个通过；最终全部 GREEN。该 RED 使用的测试快照单列归档。
- 另有 keycap 内部 rune 插入位置的 RED→GREEN，覆盖 `1️⃣X` 的所有 5 个 rune 边界，确保显示投影不改变 Position。
- 初始测试错误地要求滚动边缘必须显示光标后的字符，且要求极短字段完整显示五字符尾部；随后发现测试使用的 `ansi.Cut` 自身也不能可靠切 keycap。最终改用唯一标记的原始字节位置与可见前缀宽度，保留这些失败测试／日志，不当作产品失败或放宽字号／边界。
- 第一种重算尝试未重新建立两端窗口，未通过；keycap 初次投影及光标位置修正分别保留。归档的原生套件不能与模型尺寸状态相加为产品接受场景数。

## 正式产品的隔离 ConPTY 流程

使用 ADR-0019 的显式开发 bundle：补丁 psmux 哈希 `ca9753a059a6926bb5ad1d9fee81513507a6133d3efa5eefcf2423e33f348937`，ConPTY DLL `e971856f89748dc3b458125e9afdd79b5e9574a7c937676116d3cbbd3b71f492`，OpenConsole 文件 `b17e48b07ef153b420f0a6e178bacd31fb4c3390e21ae746586213fc0719a775`；另核对 PowerShell 7 哈希。driver 启动前校验文件，启动后核对原 server PID／FILETIME 并观测实际 DLL。未用此轮扩展系统宿主或其他平台兼容声明。

每轮使用全新目录和 namespace，只含可公开夹具。最终第六轮使用最终正式产品，70 条已执行事件为 text 13、key 27、resize 30；另保存 32 个顺序完整的原生捕获：六种表单各五个尺寸，以及两次原草稿输出观察。尺寸为 120×32 → 63×25 → 49×25 → 120×12 → 120×32。六种入口为新建名称、会话改名、搜索、分组名称、分组目录和组改名，均核对实际原生光标行及列在唯一 Q 标记之后；`!` 输入与 Backspace 后取消。

全部表单取消后回到原 shell，先确认终端焦点，再显式 Enter 一次。输出帧与独立 shell history 均保留 `Write-Output 'LONG_DRAFT'`，未由观察超时重发。前后完整 Session/Run/backend 身份相同，原 shell 仍存活。随后 F6 管理、q 正常退出，原管理器 handle 在存活时保留，实际退出码 0；再对原 Session 显式 Stop。最终管理器、原 shell、driver 均结束，强制结束产品 0、精确产品镜像剩余 0。

**这不是 Windows Terminal 桌面测试。** 没有窗口／字体／IME／物理键盘或视觉接受证据；没有打开桌面或调用剪贴板 API，也不能据此回填上一报告中首次剪贴板恢复的未知状态。

- 组内 n：捕获稳定组和默认目录，表单可覆盖或清空目录；新 Run 与初始成员关系在一个元数据事务提交。外部进程创建不原子，失败报告实际身份，禁止自动重启或停止以掩盖不确定结果。
- 稳定 Group ID 独立于名称／目录，空组保留。SQLite v4 事务迁移 v1/v2/v3；历史显示当前逻辑组，原名称／版本、Run／停止时间保留。离线检查／快照／恢复支持 v1–v4，拒绝循环／缺父组和超界树，原源库不改写；输出文件仍不含在数据库快照中。

## TDD 与本机检查

关键 RED／GREEN 和其他失败均保留在[清单](2026-11-23-custom-groups-evidence/manifest.json)：

1. 分组模型／存储 API 缺失；加入持久树及成员投影后，重开和历史保留原 Run。最初把各层 ordinal 全局排序导致子组跑到父组前，修正为前序树，失败样本保留。
2. 默认立即事务使只读工作区受另一写锁阻塞；改为驱动支持的只读事务后读取已提交快照，不把普通发现变成写者。
3. v4 被离线检查器拒绝；加入结构／树检查后，v3 升级、带名称版本的组／成员备份恢复保留时间和原身份。冲突表导致 v1/v2/v3 整个迁移回滚，源字节哈希不变。
4. 名称曾先受重命名显示长度限制；按上游清理后再检查组名显示界限，保留控制字符／非法 UTF-8／原始输入边界。
5. 嵌套树未显示、g／M 未接入、组内新建未预填目录；分别贯通后验证原 Tab／Run、一次草稿写入和没有额外启动／终端文本。
6. 在途折叠保存之后，临时揭示错误地触发追加写入；增加“明确接受的后续偏好”标记，揭示不排队落盘，原串行密度／导航／退出行为继续回归。
7. End 曾跳过空组；已选 Run 的外部成员更新曾使其藏在折叠组内；修正后保留稳定选择与可见性，不自动保存临时展开。原子投影补回原显示名校验，拒绝存储的控制字符。
8. 新占位提示补齐前得到 RED；首次 GREEN 断言直接匹配带 SGR 的字符串而失败，改为核对可见文本，原失败保留。极窄弹窗测试也曾在单列管理布局等待一个应隐藏的终端连接；修正测试前提，没有修改该产品布局行为。

# 暗／亮主题及设置行的本地验证

日期：2026-11-24；基线 `2df3c96`。按 [ADR-0032](../../adr/0032-persisted-dark-light-ui-themes.md) 推进 U20，接入固定暗／亮配色、设置主题首行与密度次行、独立 ui.toml v5。**不是完整设置面板、System 跟随、Windows 视觉或发布验收。**

## 当前体验与保存边界

管理大写 S 打开设置，默认选主题；上下／j/k／Tab 选行，左右／h/l 调整，空格轮换，Esc/S 返回。Dark／Light 与 Full／Compact／Minimal／Auto 共用既有串行整份保存，保存成功才应用。待写时合并最后两行选择，返回等待已接受写入；失败保留最后成功配色、显示未保存并取消等待关闭。仅有旧 SaveSidebarDensity 回调不能保存主题，明确报错，不把会话内变化冒充持久保存。

颜色均在 design_tokens.go，styles.go 只组合；每个 Model 独立，无可变全局主题、监视器或新依赖。上游使用角色的暗／亮背景、表面、边框、文字、暗文字、蓝、青、红、黄和紫色，共 20 个值逐项一致。行焦点有原有表面带及强调标记，非焦点选择不带下划线；短窗优先保留所选行及请求选项。布局／分隔比例不因主题改变。

应用默认前／背景继续使用既有 v2 View 机制，历史等回退视图也保留同一主题；这会改变未显式指定颜色的默认显示。原生屏幕的显式字符颜色／属性不被改写，不给目标程序注入环境、主题配置或按键。不把 RGB 常量一致当作 v1/v2 色彩降级、真实字体或整帧视觉一致；辅助 attach 的实际恢复也仍需平台复验。

ui.toml v5 的 theme 可省略（暗色），显式只接 dark／light。内部零值保持缺省，写盘省略该键，保留旧调用者零值 roundtrip。v1–v4 加载不写文件，显式保存升级 v5；旧源码读写路径拒绝 v5 并保留原文件。未知值／类型、显式空字符串、旧版本夹带 theme、未来版本拒绝，不泄露原内容。独立启动模板、SQLite v5、原 Session/Run 与终端输入边界不变；旧版拒读是迁移限制，不是兼容接受。

## RED → GREEN 与实际证据

- 配置 RED：有效 v5 light 被当作不支持的版本拒绝；UI RED：设置没有主题行。接入后配置 roundtrip、默认／显式暗色、v1–v4 只读及显式升级、坏值／旧版本字段拒绝和不覆盖通过。旧“未来 v5”设计负例推进到 v6，原字段／类型边界保留。
- 真实文件 SaveUI 回调贯通设置选择、保存、亮色应用、新 Model 恢复；原 Session/Run 与显式终端行属性保留，未向子程序写入文字／按键。它是 Go 模型服务测试，不是真实 psmux／agent。
- 屏障验证 Light 仍在写时切回 Dark 并把密度改 Auto，只有一个 writer，合并后保存最后组合再关闭；旧完成不回退。写失败保留原 Light、窄窗错误可见并取消等待返回；缺整份保存能力明确拒绝。
- 两个 Model 的颜色／样式独立，亮色不改变布局 tokens，紫色子角色不残留暗值；历史视图保持 Light。两主题 × 六宽 × 五高 × 两焦点共 120 个合成帧验证每行列数／总行数及 27×8 的所选 Dark/Light/Auto 可见。
- 原密度测试增加向下选行，保留 Full／Auto、快速轮换、失败、输入排空和终端字面 S 断言；错误提示从侧栏偏好改为界面偏好。没有通过删掉密度行为适配新首行。
- 最终 `go test ./...`、`go test -race ./...`、`go vet ./...`、`go mod verify`、500 物理行及测试目录检查通过。Windows amd64 config／CLI／UI 测试和产品仅交叉构建。339 项目录保持 designed/not_run，未把这些局部检查变成通过率。

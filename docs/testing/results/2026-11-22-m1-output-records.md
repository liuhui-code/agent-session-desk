## 实现及边界

record SESSION_ID 从实际后端重验的原目标采集一次有限屏幕，output RUN_ID 可在后端缺失或目标停止后读回。记录分别保留 record_id、Session/Run/backend、采集时刻和保留序号；source=screen_snapshot、complete=false。truncated=false 也不表示完整历史，捕获间隔、TUI 退出期间与轮转均可能有缺口，不是持续 stdout 流或模型上下文。

正文最多 64 KiB，UTF-8 安全保留尾部；已发布文件每份不超过 512 KiB，每作用域／Run 最多 2 份，同库最多 32 份，最多一份暂存。上限是逻辑文件字节与数量的工程约束，不是物理磁盘占用、全产品 RSS 或性能预算；SQLite 元数据仍有单独保留策略待做。目录读取最多取得 35 个条目以判定超限，文件读取也有字节边界。

输出正文不入 SQLite，不新增 schema、常驻进程或自动记录轮询。现有 SQLite BEGIN IMMEDIATE 锁协调同库跨进程文件操作；先捕获，再取得锁落盘。正文写入临时文件、Sync/Close 后，按保留规则移除旧捕获，再非覆盖硬链接发布。失败不会停止终端；若发布后清理失败，错误给出准确 record_id 和已发布事实。轮转与发布不是完整回滚事务，失败时旧捕获可能已清理，仍不承诺连续历史。

目录格式标记、记录字段、原身份与文件类型均核对。未知、畸形、过大或链接文件保留并拒绝，不跟随外部路径。遗留暂存不会作为已保存捕获返回，下一持锁写入仅清理保留名字空间内的自有暂存。默认 JSON 返回会转义终端控制符，未提供原始 VT 重放。

## TDD 与本地检查

[证据目录](2026-11-22-output-evidence/)保存 RED/GREEN、失败尝试、源码及二进制指纹。行为依次覆盖：重开后读回、UTF-8／截断、跨作用域每 Run 保留、目录归属、全库保留、正式文件发布、未知／过大／更强状态文件拒绝、manager 捕获与持久化边界、离线 CLI 及目标验证。

最初写最终路径再清理，外部观察发现短暂不完整／超额已发布文件；RED 保留，改为临时文件、先轮转再发布后通过。另一次保留实现遗漏内部文件名，试图删除目录而失败；错误与修正后的 GREEN 同时归档，没有把这次失败称为 Windows 产品故障。跨连接并发捕获、保留序号不重复、遗留暂存清理及身份一致性另作回归。

普通 Go、race、vet、模块、catalog、500 行检查通过；本轮无 UI 样式改动，现有 design tokens 不变。339 项目录状态仍为 designed/not_run。TC-LIFE-006、TC-STORE-017/018/019/020/021 和 TC-REC-006 的适用子行为得到局部支持；完整流日志、精确磁盘满、持续退出监测和全部场景尚未通过，不关闭整条设计用例。

同一受控 fixture 通过 TOML 自定义程序、参数和中文含空格 cwd 启动；独立 JSONL 校对实际参数／目录。连续三次 record 后只保留最新两份，Session/Run/source 与截断／不完整语义正确。完整 PID、创建 FILETIME、路径及进程 handle 独立保留。

把输出目录换成未标记目录，采集明确失败，fixture 仍活且哨兵不变；再换成指向外部合成目录的 NTFS junction，output 和 record 均在目录边界拒绝，外部哨兵与 fixture 不受影响。随后恢复自有目录、显式停止，精确 fixture handle 确认结束；后端不存在时仍读回原两份输出，已结束 Run 不能再 record，真实 list 最终为空。没有把列表为空单独当作任意进程树清理证明。

本轮没有桌面键盘、IME 或完整 attach 新验收，也没有 GitHub 工作流执行声明。交叉构建仅用于准备执行物，原生测试与 CLI 都实际在 Windows 执行。最终产物哈希及父提交见 source-manifest.json；最终工作树构建的产品与实际执行物核对一致，不标为随后 Git 提交号的正式发布构建。

# 目标程序左键输入的本地验证

日期：2026-11-24；基线 `6e41260`。按 [ADR-0031](../../adr/0031-program-left-mouse-routing.md) 补 U18 的程序鼠标路径。**仅无修饰左键的本地合同／模型；未执行原生 psmux、实体鼠标、目标 TUI、agent 或完整体验验收。**

## 当前行为与边界

活动、已连接、已聚焦的实时终端声明 WantsMouse 时，左按／左拖／左释放通过已有原 pane `pane-mouse`，不转为产品选区、文字或按键。起点只在可见内容内；拖动越过 Tab／侧栏／框仍属于原手势，坐标夹到原 pane 可见内容范围。管理焦点第一次点击只聚焦，重复按下／释放不重复提交。右／中键、修饰、无按键悬停和完整程序兼容仍开放。

程序手势与原生选择分开：CopyMode 优先既有选区；未声明鼠标的实时终端继续 ADR-0030 的直接拖选。对原生选区，取消仍不合成释放或复制。对已接受的程序按下，键盘、粘贴、滚轮、主动切 Tab／管理视图和 resize 前，以最后接受坐标向原队列入队一次释放，再处理下一动作；无按钮运动或不支持的修饰运动也结束该程序手势。不重试，不转投新 Run。

程序手势活动期间，输入 FIFO 至多使用 64 个等待位置中的 63 个，保留一个释放位置；活动 writer 另计。过量运动拒绝且提示，最后接受坐标不被拒绝事件改写。200 次受控运动中，等待队列停在 63，随后真实释放填入第 64 个位置；包括 writer 中的按下，共 65 次被记录的指针调用，释放仅一次。这是传输防御，不是资源预算／延迟保证。

原连接代次、内容矩形、实际后端屏幕宽高和模式分别绑定。外部帧改变模式／鼠标声明／提示或屏幕尺寸时，即使随后恢复也只清除本地所有权并提示“释放结果未知”；不把释放写到另一模式，避免进入复制模式后意外复制。异常断开／强制 UI 关闭也不能保证原程序已释放。WantsMouse 是帧声明，不是完整程序能力或输入已处理的证明；帧与命令之间仍没有模式锁。

无新协议、依赖、样式值、服务、剪贴板读取、第二份历史或存储版本。程序是否接受事件、VT／Win32 注入和拖动时按钮状态必须真实程序独立核对。普通 CLI 与 agent 继续使用原终端输入，没有日常聊天框。

## RED → GREEN 与本地证据

- 程序路径 RED：声明鼠标的实时程序没有收到左键序列；接入后收到原 pane 内容坐标的按下、拖动、释放，没有 copy-drag、键或文字替代。
- 释放 RED：切 Tab 前只有按下／拖动，没有释放。主动动作先结束原程序手势后 GREEN；屏障证明原 Run 先排空，第二 Run 仅收到独立文字 z，旧物理释放不续接。
- 尺寸 RED：只比较可见裁切宽度，会漏掉后端屏幕变大再恢复，旧释放仍发送。改为绑定实际屏幕宽高后 GREEN，恢复尺寸不恢复所有权。
- 九个新 UI 顶层／含子测试共 27 个模型服务测试，覆盖原内容坐标、跨控件夹取、重复事件、八种主动结束、四种外部失效、六种非启动状态、复制模式优先与单释放位置压力。既有复制／直接拖选回归继续通过；旧“声明鼠标的实时程序不启动”负例按新能力移交新正例，管理／提示／边框／修饰等边界保留。
- 用独立 Go overlay 仅去掉释放保留判断，压力测试明确 FAIL，正式代码未修改；该负向用例是故障注入敏感性证据。两轮行为 RED 与尺寸 RED 均保留，不把故障注入称作原生 psmux 失败。
- 最终 `go test ./...`、`go test -race ./...`、`go vet ./...`、`go mod verify`、500 物理行检查及目录校验通过。Windows amd64 terminal／UI 测试和产品仅交叉构建，未执行；339 项目录用例仍 designed/not_run。

## 3. 环境与测量口径

最终 runner 为 Windows Server 2025 Datacenter `10.0.26100` / X64，`ImageOS=win25-vs2026`、`ImageVersion=20261116.315.1`，4 个逻辑处理器、16,771,836 KiB 可见内存，PowerShell 7.6.10、Go 1.27.4。psmux 3.4.0 使用固定官方发行物；执行文件 SHA-256 为 `bbe825a30f7cddc91b043084049143a381aba5f7e9e36e4d0bb587e296d262ca`。产品、fixture 与 driver 各拷贝的实际哈希见摘要，25 个 Go/module 源文件运行前后字节指纹与该提交一致。[环境与哈希][index]

产品 TUI 在独立测量用 psmux 的 120×32 ConPTY 中运行，后台历史上限 2000 行。该 driver 是无桌面 CI 的测量脚手架，不是新增产品常驻 Host。driver 与 PowerShell sampler 单列；共享 WMI 开销和脚手架对调度/绘制的影响不能通过相减消除。没有采集整机内存或整机 CPU 计数。

0/1/5/10 档位执行空闲及 TUI 关闭/重开；1/5/10 执行选中会话输出与恢复空闲；5/10 另执行全部输出。直接管道对照为 1/5/10 个相同 fixture 的空闲与全部输出。每阶段先等待 3 秒，再以约 1 秒间隔采样 12 秒；负载目标是每进程每秒 100 行、每行 256 字节（含 LF）、持续 25 秒。34 次负载均完成，实际各为 **2191–2500 行**，真实写入字节均为行数 × 256；全部覆盖对应采样窗口，并在结束后收到输入标记。配置速率不等同于每次都实现精确 2500 行。

以下内存单位为 **MiB，单元格为 Private Bytes / Working Set，取同步分组求和后的 p50**。私有字节表示私有提交内存；工作集表示驻留页，跨进程工作集相加可能重复共享页，不是独占物理内存。两列不能相加。完整表另列 Type 7 p95、最大值、句柄、线程与读取覆盖率。未把各进程不同时间的峰值相加，也不以零填补缺测。官方定义与复现命令见 [WINDOWS_RESOURCES](../WINDOWS_RESOURCES.md)。

## 5. 生命周期、归属与缺口

16 个托管 Session/Run、backend server 与 fixture 身份在 UI 关闭/重开后保持；总计 8 次 TUI 启动均有实际屏幕文本和 `q` 正常退出、exit code 0 的记录。64 次产品后端选项读取以及 16 次 driver 选项命令均确认 `warm=off` / `warm-pool-size=0`。观测到的 server 数量与各场景一致，不能据此声明所有可能短命/不可见进程均已被排除。[事件与原始快照][zip]

修复后，每个被采到的后端 server 和测量 driver 均有两个已验证归属的 `console_aux`，路径身份不匹配为 **0**。归属使用 PID、准确 FILETIME 与路径，并保留父进程退出后的既有后代身份；没有用 registry 残留或进程同名来代替活身份。7 次正常清理均得到 `remaining_owned_processes=[]` 和 `collection_gaps=[]`，无强制兜底。这证明已验证归属的进程（包括辅助进程）在这些清理检查中退出，不构成任意未知进程或长期无泄漏保证。

全 280 次快照仍记录 **14 条 `process_read_failed`**，分布在 13 个阶段样本；另有 128 条 `previous_owned_not_observed`，后者是既有身份离场观察，不自行当作计数读取失败：

- `managed-5 / recovery-idle`：同一快照有两条读取失败，其中一条有后端拷贝的 CIM 路径、一条无路径；完整内存观察为 **11/12**。
- `managed-10 / all-output`：12 个样本各有一个不同 PID 的读取失败，CIM 名称为 `psmux.exe`、父 PID 为当前 TUI，但实际 image path / FILETIME 未能完成核验。因此保持未知归属，完整内存观察为 **0/12**，CPU 完整配对为 **0/11**。这与快速退出的控制客户端竞争相符，只是推断，不能补写为已认证身份。
- 其余 20 个阶段为 **12/12** 完整内存观察。该“完整”只指当次观察中没有已知读取缺口，**整个进程总体及全生命周期仍未证明完整**。

CPU 按相邻快照同一身份累计时间差计算，100% 表示一个逻辑核，报告已观察下界。10 会话空闲时 TUI 为 **4.63%**，产品及 fixture 合计 **5.78%**；全部输出时合计 **27.82%**，但有上述缺口。不能按一秒快照推算所有短命 CLI 的完整 CPU；不同轮次的数值变化也不能在没有对照实验时归因为产品性能改善。

采样本身也有成本：0/1/5/10 空闲时单次采集耗时 p50 约为 28/37/55/68 毫秒，sampler/driver 的详细组值另列。这里没有用实验脚手架的资源之和假装普通用户 Windows Terminal 的整机占用。

## 6. 决策与后续门槛

当前证据支持继续现有 Go / Charm v2 与隔离后端路线，同时把优化优先级放在两个可测方向：后台会话发现/预览的控制命令开销，以及输出后的后端历史保留。后端成本随会话数和输出历史增长，TUI 进程较稳定；本轮未因此更换架构、增加产品 Host 或批准任何数字预算。

接下来仍需覆盖 `TC-PERF-001` 的每档 5 分钟准备加 15 分钟采样、对应 15/30 分钟空闲，以及 8/24 小时长稳。应补充短命进程的完整生命周期计量，才能讨论精确总 CPU 与全部增量开销。Windows 11 / Windows Terminal、字体/IME、焦点、resize、交互 attach/分离、真实本地 agent 与安装发布均未由本轮验证。该 hosted 镜像含 WSL，实际走原生程序路径，不证明无 WSL 安装场景。

**339 条设计用例保持 `designed/not_run`，FL-003/006/015/016 仅增加局部证据，M0 仍未验收。** 测试设计、执行事实和发布承诺分别维护。文档同步至 [Feature Ledger](../../FEATURE_LEDGER.md) 与 [ADR-0003](../../adr/0003-bounded-resources-and-background-work.md)。

# 测试夹具与故障注入合同

日期：2026-11-21。**下面是完整测试基础设施的设计合同，尚未全部实现。** 当前 `cmd/asd-fixture` 已提供参数／环境／输入／退出的独立 JSONL 观察，并用于[原生 Windows 后端验证](results/2026-11-21-m0-native-windows.md)；它不等于本文所有合作协议、故障钩子与负载夹具已实现。这些设施给后续用例提供可重复输入和独立观察，不是新的 agent 接入前提。

## 通用约定

每轮分配独立 `test_run_id`、数据目录和后台 namespace。输入使用固定种子和公开假数据。夹具可写带序号的 JSONL 观察日志，包含单调事件序号、来源 Session/Run、原始字节或校验值，以及必要时间。

产品可获得的证据与测试观察器的证据分开保存。测试观察器知道 agent 收到了某字节，并不允许产品凭空显示 accepted；产品只依据实际接入能力。默认 CLI 不因测试夹具提供旁路观察而自动获得增强协议。

### FX-ECHO

可构建为原生可执行文件；脚本启动路径用等价包装层单独验证。记录真实 argv、cwd、限定的测试 env，以及收到的输入字节和提交事件。支持空参数、引号、反斜杠、多行与 UTF-8 分片。保留原始字节与规范化后的文本两种观察，换行/终端行规处理按具体合同对照，不硬性假定所有输入等同于原文件字节。

不得回显真实凭据；只使用本轮生成的哨兵值。它是普通终端夹具，默认没有 ready/accepted/completed 能力。

### FX-VT

生成有确定坐标与序号标记的屏幕：颜色、光标、擦除、alternate screen、滚动区、长行、CJK/组合字符，以及拆分到不同读取块的 VT/UTF-8。记录当前终端尺寸和收到的键/查询回复。

正常序列与异常/超长/未终结序列分组，输出仅发生在测试终端。屏幕 golden 结果按已声明终端能力和尺寸比较；不能把所有终端字体差异当成产品缺陷，也不能以“看起来差不多”忽略错行错字。

### FX-READY

合作式测试 agent，提供明确且可关联的 ready/busy/approval、接收、完成、进度与 reply_to 事件。事件包含来源 Run 和序号，可控制重复、延迟、断开、旧 Run、乱序和缺失。

自动投递的就绪来源必须走产品已实现的适配能力；测试日志不能偷偷充当产品信号。支持 A/B/C 协作，命令调用结果实际进入夹具的工具输入，不以终端出现一段命令文字证明工具已执行。具体协议随测试适配器实现确定，通用 CLI 接入仍不要求它。

### FX-ATTENTION

合作式人工介入事件源，按 [ADR-0006](../adr/0006-human-attention-and-notifications.md) 提供待批准、待回答、待检查、请求已处理及已撤销等可关联证据。记录可信来源绑定、Session、Run、人工介入请求身份、事件身份与版本/序号；支持同请求重复、同文不同请求、先解决后迟到创建、旧 Run 重放、断连、事件缺失，以及重连后的未结束请求快照。

与 FX-PROCESS 联合覆盖 Run 退出：原审批/提问请求失效，异常退出可形成绑定已结束 Run 的独立待检查事项。用户明确标记“已检查”只改变该检查事项并保留人工来源，不由夹具伪造 Agent 批准、接收或任务成功事件。

夹具维护独立的实际请求状态，测试观察器可据此判断误报和漏报。产品只能通过已配置且实现的适配入口收到证据，不能直接读取该观察日志。普通终端输出中的问号、批准文本、仿冒事件 JSON、历史滚动内容和静默场景作为独立对照，不自动取得可信事件的地位。

事件格式、来源验证、同请求更新规则、重连快照完整性和新鲜度由 `TBD-ATTENTION-EVENTS` 固定。夹具的控制器不强制产品采用某种 IPC，也不能用测试端的完整快照偷偷弥补产品已丢失的证据；无可靠对账能力时应能验证“待处理但当前状态待确认”。

### FX-NOTIFY

可控通知出口与激活观察器，记录通知请求、作用域、会话/Run/事项绑定、尝试编号及合成正文；可返回拒绝、超时、明确接受和接受后丢回执，也可延迟、重复或回放点击/关闭回调。支持注入多个消费者竞争与通知发送后进程崩溃，不声称操作系统具有端到端 exactly-once 通知能力。

假出口只验证路由、去重、策略和恢复逻辑。接口报告发送成功不代表横幅已显示，更不代表用户已读、Agent 已接收批准或问题已解决。记录应用内事项、发送尝试、OS 可观察结果和人工确认四种证据，不能共用一个“成功”标志。

真实 Windows 通知、安装注册、已有进程/冷启动激活、免打扰、通知禁用、终端 BEL 与 psmux 传播须在 Windows 环境独立验证。`TBD-WINDOWS-NOTIFY` 决定接入和支持范围，`TBD-ATTENTION-POLICY` 决定稍后提醒、节流和保留策略。全部载荷使用假数据；标题、摘要和点击参数中的引号、控制字节与合成敏感标记，不应变成 shell 命令、终端输入或无关会话操作。

### FX-PROCESS

控制启动延迟、立即退出、退出码、shell 留存、子进程和拒绝正常停止等行为。观察 PID 与启动时间/生成标记，支持模拟 PID/pane 标识复用。停止仅针对本轮进程，不按名称终止其他用户任务。

真实停止/重启语义按 TBD-LIFECYCLE 固定；夹具不强迫实现使用某一种进程树 API。

### FX-DATA

生成隔离的配置、数据库副本、消息正文、带校验值输出和路径样本。包含中文/空格/引号、空值、控制字符以及 B−1/B/B+1 边界。记录生成种子、schema 和数据哈希。

损坏数据库、只读/占用文件、清理越界和迁移故障都使用副本。磁盘耗尽使用专用小容量测试盘；不得填满运行环境或改动用户真实目录。测试链接/联接点只能指向另一测试哨兵目录。

### FX-FAULT

在边界设置可控屏障：测试到达某点后暂停，采集证据，再断开通道、返回错误或终止指定测试进程。仅测试构建/适配器暴露钩子，生产能力不由这些钩子定义。

| 屏障 | 时点 | 主要观察 |
| --- | --- | --- |
| F-QUEUE-BEFORE-COMMIT | 入队事务提交前 | 调用结果、是否存在持久请求、目标是否被写入 |
| F-QUEUE-AFTER-COMMIT | 请求已持久化、响应未送回 | 幂等重试是否定位同一请求 |
| F-DELIVERY-CLAIMED | 已领取/记录尝试、第一次写入之前 | 恢复时是否有可靠“尚未写入”证据 |
| F-INPUT-PARTIAL | 仅有部分输入可能写出 | 不允许完整 input_written 或无条件重放 |
| F-INPUT-AFTER-WRITE | 写完、回执落盘之前 | 外部执行可能发生；产品状态仍需保留不确定性 |
| F-RECEIPT-AFTER-COMMIT | 写入回执已经持久化 | 重启不能因为缺 agent 完成证据重发指令 |
| F-RUN-RECHECK | 初次检查目标后、最终投递前 | 重启、pane/PID 复用与目标身份重新核对 |
| F-INPUT-OWNERSHIP | readiness 检查后、占用输入前 | 用户 attach 与多个发送者的交接 |
| F-OWNER-PAUSED | 旧 Host 暂停，竞争者试图接管 | 旧所有者恢复后不能产生双写 |
| F-STORE-MIGRATE | 配置/数据库迁移边界 | 中断后的格式、身份和恢复路径 |
| F-CAPTURE-DELAY | capture 返回前 | 过期结果不能覆盖另一会话预览 |
| F-ATTENTION-AFTER-COMMIT | 人工介入事项已持久化，界面/通知尚未消费 | 重开仍能找到同一事项；不通过换 ID 制造多个待办 |
| F-NOTIFY-AFTER-SHOW | 通知出口已接受，发送结果尚未在本地记账 | 保留发送结果不确定性；恢复不把外部通知假称已读或已解决，也不无限重发 |
| F-ATTENTION-ACTIVATE | 点击已到达，最终核对事项及 Run 之前 | 同时退出/重启/解决请求时，只导航到核对后的对象或历史，不向新 Run 写入答案 |
| F-ATTENTION-RECONCILE | 事件源重连后，未结束事项对账完成前 | 缺失或迟到事件不自动清待办，不复活已解决的旧事项；不把不完整快照当完整事实 |

表中名称是测试合同，不规定数据库字段、锁类型或 IPC 实现。用例也可以用中文时点描述同一屏障。对真实 OS 难以稳定触发的竞态，先在合同层控制调度，再以原生集成验证真实路径。

### FX-CLOCK

可控制的壁钟、单调计时与事件序号。通过测试接口注入前进、回拨、超时边界，不更改共享宿主的全局时间。时间显示与消息/Run 身份分开；TTL 和就绪信号时效仍需明确产品策略。

### FX-LOAD

确定性空闲、匀速、突发、无换行长行、CJK 与 VT 重绘负载。每个来源有独立序号和校验值，固定输出速率、块大小、总量、会话数与持续时间。

资源报告保留原始测量；负载夹具自身的 CPU/内存计入 agent 组。长稳保留所有失败轮次，不能只挑选稳定的一轮报告。

### FX-RELEASE

干净 Windows VM/测试用户、明确发布物与依赖、安装说明和可回退快照。可关闭外部网络，用本地夹具验证管理流程；这不要求真实模型 agent 能离线推理。

记录安装路径、数据目录、PATH、后台二进制哈希、升级前后 schema 和发行清单。安装/卸载只处理测试实例，结束后核对其他 namespace 未受影响。

## 实现顺序与完成证据

M0 先做 FX-ECHO、FX-VT、FX-PROCESS 和最小 FX-DATA；M1/M2 补存储与后台边界，并按 FL-020 实现 FX-ATTENTION、FX-NOTIFY 的最小合同及 attach 期间提醒验证；M3 完善 FX-READY、FX-FAULT、FX-CLOCK 和共享 Host 的事件交接；M4 完善长稳采样与干净发布环境。M2 不因提醒功能而默认要求自有常驻 Host。

每个夹具需验证自身输出可信，再用来判断产品；夹具错误时，相应产品验收应标 blocked，不能把它算成产品通过或失败。CI／测试进程本身仍需如实记录失败退出码。已有 M0 可控 CLI 和少量原生故障场景的局部结果见[执行报告](results/2026-11-21-m0-native-windows.md)，其余完整夹具和屏障仍按设计逐步实现。

# 阶段路线图

状态：M0 首批源码迁入与原生 Windows 自动化已落地，继续完整流程验证。更新日期：2026-11-22。初始规划基线：2026-11-20。

阶段按可验证结果推进，暂不承诺固定周数。Go/Charm v2、选择性 UI 复用及 Windows psmux 路线已经记录，具体移植范围、兼容性与资源预算由 M0 确认。选型见[技术栈](TECH_STACK.md)及 [ADR](adr/README.md)，初始需求见[产品计划](PRODUCT_PLAN.md)，实际状态与证据见 [Feature Ledger](FEATURE_LEDGER.md)。

**当前没有已完成的软件阶段。** 已在指定 Windows Server 2025 runner 通过常规检查与五项可控原生后端场景，完整记录见[Windows 执行报告](testing/results/2026-11-21-m0-native-windows.md)。另有[原生 Windows 短资源实验](testing/results/2026-11-21-m0-windows-resources.md)，覆盖 0/1/5/10 会话、真实 TUI 启停与直接程序对照。这些局部证据不代替 Windows Terminal 桌面交互、完整资源预算与 M0 验收；M4 发布前还必须复验对应发布组合。

2026-11-22 技术进展：[ADR-0015](adr/0015-pinned-psmux-native-terminal-client.md) 已实现固定 psmux 原生终端传输，并通过 fixture／普通 PowerShell 的两项局部原生测试；ADR-0016 在 2026-11-23 接入首个 psmux Tab UI，并有普通 shell 的[局部桌面证据](testing/results/2026-11-23-tab-workspaces.md)。完整上游视觉／交互、IME、子程序鼠标、滚动／排序与资源门槛保持开放。

## M0：视觉基线与 Windows 可行性

目标：验证 Agent Deck 的简约界面代码可以迁入稳定 Charm v2，并通过 psmux 在原生 Windows 完成最小闭环。

交付物：

- Agent Deck UI 来源清单，标明固定提交、许可证、保留的样式/列表/弹窗/快捷键，以及需要替换的状态和后端调用。
- Agent Manager Windows 适配代码的复用边界与 psmux 调用合同；记录 UI 对 tmux/Unix 的耦合及处理方式。
- Go 1.27 与稳定 Charm v2 的构建验证；完成迁入 v1 来源代码的必要适配，精确版本按 ADR-0005 和技术栈锁定。
- 一个 Windows 原生运行的界面和终端验证切片；模拟数据与真实 agent 输出明确区分。
- psmux 3.4.0 稳定发布的创建、预览、输入、resize、退出检测、attach/detach 与重连结果，记录实际二进制来源/哈希；不将 master 的实验能力当作稳定发布能力。
- 禁用本产品非必要预热后的进程树与资源基线；TOML 配置、SQLite 元数据/消息及有界日志文件的最小存储方案，数据库驱动和预算在验证后确定。

验收：

- Windows 实机中验证中文/IME、多行粘贴、宽字符、光标、颜色、resize、Ctrl+C、焦点和基本输出性能；v1→v2 迁入后的布局与输入行为有回归结果。
- 原生路径不依赖 WSL；测试环境及版本可复现。
- 对照固定上游核对布局比例、配色、间距与交互，列出 Tab 主导航及必要平台差异；验证 Tab 内终端的屏幕、输入和尺寸方案。全屏 attach 仅作辅助路径；不以 v0.1 概念图作为界面通过依据。
- 视觉与交互有真实运行截图/录屏或可运行版本依据；界面接受与终端兼容分别记录。
- 不仅根据框架“支持 Windows”的声明选择整个应用底座。

对应需求：FR-01、FR-02、FR-11 的技术预验证。

阻断条件：未通过上述 Windows 关键路径时，不声明原生 Windows 已支持，也不发布标为已兼容的预览包；必要时在 ADR 中记录调整后的后端或复用范围。首轮不同时开发另一套直接 ConPTY 托管与终端仿真。

## M1：单会话完整流程

目标：从一条自定义命令到稳定可操作的会话。

当前局部进展（2026-11-22）：显式只读 TOML 启动模板及 CLI 覆盖已有实现与 [Windows fixture 证据](testing/results/2026-11-22-m1-config-tokens.md)。真实 agent 验收、配置保存及完整记录存储仍未完成，M0 剩余门槛继续保留。

最小会话元数据切片已实现：SQLite 驱动、schema v1 和事务合同见 [ADR-0009](adr/0009-session-run-metadata.md)，局部验证见[实际报告](testing/results/2026-11-22-m1-metadata.md)。pane 退出观测与 v1→v2 追加迁移现见 [ADR-0010](adr/0010-pane-exit-observations.md)；数值退出码仍未知。按需只读 TUI 历史与详情见 [ADR-0011](adr/0011-read-only-tui-history.md)，只覆盖最近 100 条；离线检查、快照和非覆盖恢复已有 [ADR-0012](adr/0012-metadata-checkpoint-recovery.md) 及[局部执行](testing/results/2026-11-22-m1-metadata-recovery.md)，完整历史查询与异常矩阵仍需验证。agent 接入沿用现有自定义 CLI／TOML 模板，不另建品牌适配阶段；真实 CLI 仅作为通用启动流程的验收样本，既有 Windows 回归门槛保留。

M1 收尾已加入[离线检查、备份和非覆盖恢复](adr/0012-metadata-checkpoint-recovery.md)及真实 SQLite 进程中断回归。用户当前没有实际 agent，继续按自定义命令／目录配置化实施；真实 agent 兼容性保留待测，不用可控 fixture 冒充。剩余输出文件记录与最终流程验证见 [M1 验收清单](testing/M1_ACCEPTANCE.md)。

M1 收尾按[验收清单](testing/M1_ACCEPTANCE.md)推进；显式有界屏幕记录与离线读取已有 [ADR-0013](adr/0013-bounded-screen-output-records.md) 和[Windows 局部结果](testing/results/2026-11-22-m1-output-records.md)，连续流日志不在此能力声明中。用户目前没有实际目标 agent，继续以自定义命令／工作目录的配置化实施；真实 agent 兼容性不得由 fixture 冒充，仍保留待测。

交付物：启动配置、Session/Run 身份、工作目录和环境处理、单 Tab 内完整终端输入／显示、辅助预览与全屏 attach、停止和失败说明，以及最小记录存储。普通 shell／CLI 与 agent 同属管理对象；首个 psmux Tab 工作区已有局部实现与实机结果，完整交互与视觉仍待验收。会话核心随 TUI 或管理命令运行；本阶段不强制启动自有常驻 Host。

验收：

- 使用可控测试 CLI、普通交互 shell 和实际目标 agent 经配置接入；在单 Tab 的终端原生输入区操作，shell 命令结束后可继续输入，不要求 agent 协议或额外聊天框。真实 agent 未安装时保留待测。
- 会话切换前的基础输入、退出码、进程结束和输出记录行为明确。
- 被动预览不持续改变正在使用的终端尺寸；agent 退出但 shell 留存时，不能把终端后台存活当作 agent 存活。
- 不要求目标 agent 实现专用通信协议。

对应需求：FR-01、FR-02、FR-10、FR-11。

## M2：多会话与终端后台托管

目标：并行管理多个会话，关闭界面后由 psmux 继续托管原 Run。

交付物：多 Tab 工作区、命名、辅助列表／分组／搜索、psmux 后台发现与重新连接、基础历史与归档；按 [ADR-0006](adr/0006-human-attention-and-notifications.md) 增加可靠人工介入事件、持久待处理事项、原因标记、汇总/定位及管理器存活时的可选 Windows 通知。默认使用 Tab 承担导航；切换保留终端未提交输入，关闭视图不停止 Run，重新打开接回原 Run；视图与 Session/Run 身份分离。M2 不要求本产品再启动一层常驻终端宿主。

验收：

- 多会话切换不重启进程，不把输入发到错误目标。
- 关闭 TUI 后后台保持存活；重新打开接回同一个 Run。
- agent 已退出或后台已断开时，列表和详情状态一致。
- 重命名、排序和视图关闭不改变 session_id。
- 输出缓存有边界，后台会话不持续生成完整预览；关闭 TUI 释放其缓存，psmux 继续托管终端。
- 在 A 输入时，B 的可靠审批/提问事件可被发现并定位；attach 中事件接收不随绘制暂停，不抢焦点或向原终端插入文字。查看、稍后提醒与事项解决分离，重复/乱序/旧 Run 不产生误提醒或误定位。
- 原生通知验证支持范围内的发送、禁用/失败降级与点击目标核对；精确 API、注册和键位先固定实施合同，M4 再用发布包复验。未知 CLI 及仅文本识别不得显示未经证明的确定状态。

对应需求：FR-03、FR-04、FR-05、FR-10、FR-11、FR-14 的管理器存活路径。

本阶段完成的“后台”是终端持续托管，不代表消息队列已能在 UI 关闭后自动消费，也不保证人工介入仍被监测；持续消费与提醒在 M3 验收。

## M3：跨会话读取与消息投递

目标：完成从请求到可核对回执的通信流程。

交付物：输出游标、来源标记、SQLite 消息收件项、显式投递与按能力自动投递策略、回执、管理 CLI 及使用说明。启用后台自动消费或持续提醒时使用一个共享轻量 Host，负责已启用能力的就绪/人工介入事件、消息策略、通知与发送仲裁；继续由 psmux 托管终端。Host 的 IPC 选择在实现前记录，不预先指定未经验证的传输。

验收：

- 用户可读取并转发指定会话的输出片段。
- 有命令执行工具的 agent 可通过管理 CLI 主动读取、发送和查询状态。
- 投递始终使用稳定 session_id，不依赖 Tab 顺序。
- 管理器只显示已获得证据的消息阶段；输入写入不能升级为任务完成。
- 对有可靠状态信号的接入验证自动排队；对未知 CLI 验证降级行为。
- 单独验证 UI 关闭、共享 Host 存活时的自动消费；无消费者时队列落盘保留且不显示虚假进度，重新打开后可以继续处理。FR-08 不因前两阶段没有自有 Host 而被省略。
- 同一目标的多发送者与用户输入有协调规则；消息正文、粘贴与提交不能交错进入错误上下文。
- 使用合作式测试 agent 验证请求与回复关联，明确返回结果的来源。
- 覆盖目标退出、后台断开、重试以及投递结果不确定。
- 目标 Run 变化后，旧队列消息暂停，不自动投递到新上下文。
- 单独验证 UI 关闭后、Host 存活时的人工介入记录和通知；无消费者时明确监测空档，重开仅按可用证据对账。审批等待不被普通队列输入覆盖，多实例、可选 hook 与 Host 之间不出现重复通知风暴。
- 覆盖事项已存但通知未发、系统已接受但本地回执未存、消费者切换及恢复；应用事项与外部通知结果分离，不承诺横幅 exactly-once 或用户一定已读。

对应需求：FR-04、FR-06、FR-07、FR-08、FR-09、FR-12、FR-13、FR-14 的后台路径。

## M4：打磨与预览发布

目标：提供一个可安装、可诊断、可回退的 Windows 预览版本。

交付物：主题与快捷键打磨、配置迁移规则、安装/升级/卸载说明、已知限制、兼容矩阵、发布包与版本说明。

验收：

- 用户从发布包完成配置、启动、切换、通信、重连这一整条流程。
- 明确最低 Windows 版本、已验证架构、终端与目标 agent 版本；具体范围由实测确定。
- M0 关键路径在最终锁定的依赖和发布包上复验，不能仅沿用开发阶段或上游项目的结果。
- 核对发行物中的依赖、许可证与必要归属信息。
- 记录性能基线，检查持续输出和多会话情况下的输入响应。
- 发布说明区分已支持、实验性和不支持的能力。
- 从发布包复验人工介入提醒、通知注册/卸载、已有进程与冷启动激活、过期通知、权限/免打扰及已声明的渠道降级；记录实际通知与监测能力，不把假出口测试作为 Windows 通过依据。

对应需求：全量首版验收。

## 阶段调整规则

如 M0 证明选定来源耦合过重或后端无法覆盖必要命令，可以保留合适的视觉与交互，调整代码复用范围或后端实现；不得把未验证的复用比例、兼容性或性能作为承诺。改变已接受方向时创建替代 ADR，记录原因、影响的 FR/FL 编号与新证据，保留原决定历史。

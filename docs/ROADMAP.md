# 阶段路线图

状态：按已记录技术路线推进，尚未开始产品实现。更新日期：2026-11-21。初始规划基线：2026-11-20。

阶段按可验证结果推进，暂不承诺固定周数。Go/Charm v2、选择性 UI 复用及 Windows psmux 路线已经记录，具体移植范围、兼容性与资源预算由 M0 确认。选型见[技术栈](TECH_STACK.md)及 [ADR](adr/README.md)，初始需求见[产品计划](PRODUCT_PLAN.md)，实际状态与证据见 [Feature Ledger](FEATURE_LEDGER.md)。

**当前没有已完成的软件阶段或 Windows 实机结果。** 文档中的已接受方向不代替运行验证。M0 是原生 Windows 路线的首个门槛，M4 发布前还必须复验对应发布组合。

## M0：视觉基线与 Windows 可行性

目标：验证 Agent Deck 的简约界面代码可以迁入稳定 Charm v2，并通过 psmux 在原生 Windows 完成最小闭环。

交付物：

- Agent Deck UI 来源清单，标明固定提交、许可证、保留的样式/列表/弹窗/快捷键，以及需要替换的状态和后端调用。
- Agent Manager Windows 适配代码的复用边界与 psmux 调用合同；记录 UI 对 tmux/Unix 的耦合及处理方式。
- Go 1.27 与稳定 Charm v2 的构建验证；完成迁入 v1 来源代码的必要适配，精确版本按 ADR-0005 和技术栈锁定。
- 一个 Windows 原生运行的界面和终端验证切片；模拟数据与真实 agent 输出明确区分。
- psmux 3.4.0 稳定发布的创建、预览、输入、resize、退出检测、attach/detach 与重连结果，记录实际二进制来源/哈希；不将 master 的实验能力当作稳定发布能力。
- 禁用本产品非必要预热后的进程树与资源基线；TOML 配置、SQLite 元数据/消息及有界日志文件的最小存储方案，数据库驱动和预算在验证后确定。

验收：

- Windows 实机中验证中文/IME、多行粘贴、宽字符、光标、颜色、resize、Ctrl+C、焦点和基本输出性能；v1→v2 迁入后的布局与输入行为有回归结果。
- 原生路径不依赖 WSL；测试环境及版本可复现。
- 管理状态保持列表与当前预览，进入会话后全屏操作，分离后恢复管理器；不以 v0.1 概念图作为界面通过依据。
- 视觉与交互有真实运行截图/录屏或可运行版本依据；界面接受与终端兼容分别记录。
- 不仅根据框架“支持 Windows”的声明选择整个应用底座。

对应需求：FR-01、FR-02、FR-11 的技术预验证。

阻断条件：未通过上述 Windows 关键路径时，不声明原生 Windows 已支持，也不发布标为已兼容的预览包；必要时在 ADR 中记录调整后的后端或复用范围。首轮不同时开发另一套直接 ConPTY 托管与终端仿真。

## M1：单会话完整流程

目标：从一条自定义命令到稳定可操作的会话。

交付物：启动配置、Session/Run 身份、工作目录和环境处理、终端预览与全屏 attach、停止和失败说明，以及最小记录存储。会话核心随 TUI 或管理命令运行；本阶段不强制启动自有常驻 Host。

验收：

- 使用至少一个可控测试 CLI 和一个实际目标 agent 验证，二者都通过配置接入。
- 会话切换前的基础输入、退出码、进程结束和输出记录行为明确。
- 被动预览不持续改变正在使用的终端尺寸；agent 退出但 shell 留存时，不能把终端后台存活当作 agent 存活。
- 不要求目标 agent 实现专用通信协议。

对应需求：FR-01、FR-02、FR-10、FR-11。

## M2：多会话与终端后台托管

目标：并行管理多个会话，关闭界面后由 psmux 继续托管原 Run。

交付物：简约列表、命名、分组/搜索、会话视图、psmux 后台发现与重新连接、基础历史与归档。默认使用列表承担导航；视图与 Session/Run 身份分离。M2 不要求本产品再启动一层常驻终端宿主。

验收：

- 多会话切换不重启进程，不把输入发到错误目标。
- 关闭 TUI 后后台保持存活；重新打开接回同一个 Run。
- agent 已退出或后台已断开时，列表和详情状态一致。
- 重命名、排序和视图关闭不改变 session_id。
- 输出缓存有边界，后台会话不持续生成完整预览；关闭 TUI 释放其缓存，psmux 继续托管终端。

对应需求：FR-03、FR-04、FR-05、FR-10、FR-11。

本阶段完成的“后台”是终端持续托管，不代表消息队列已能在 UI 关闭后自动消费；该能力在 M3 验收。

## M3：跨会话读取与消息投递

目标：完成从请求到可核对回执的通信流程。

交付物：输出游标、来源标记、SQLite 消息收件项、显式投递与按能力自动投递策略、回执、管理 CLI 及使用说明。启用后台自动消费时增加一个共享轻量 Host，负责就绪事件、消息策略与发送仲裁；继续由 psmux 托管终端。Host 的 IPC 选择在实现前记录，不预先指定未经验证的传输。

验收：

- 用户可读取并转发指定会话的输出片段。
- 有命令执行工具的 agent 可通过管理 CLI 主动读取、发送和查询状态。
- 投递始终使用稳定 session_id，不依赖 Tab 顺序。
- 管理器只显示已获得证据的消息阶段；输入写入不能升级为任务完成。
- 对有可靠状态信号的接入验证自动排队；对未知 CLI 验证降级行为。
- 单独验证 UI 关闭、共享 Host 存活时的自动消费；无消费者时队列落盘保留且不显示虚假进度，重新打开后可以继续处理。FR-08 不因前两阶段没有自有 Host 而被省略。
- 同一目标的多发送者与用户输入有协调规则；消息正文、粘贴与提交不能交错进入错误上下文。
- 使用合作式测试 agent 验证请求与回复关联，明确返回结果的来源。
- 覆盖目标退出、后台断开、重试以及投递结果不确定。
- 目标 Run 变化后，旧队列消息暂停，不自动投递到新上下文。

对应需求：FR-04、FR-06、FR-07、FR-08、FR-09、FR-12、FR-13。

## M4：打磨与预览发布

目标：提供一个可安装、可诊断、可回退的 Windows 预览版本。

交付物：主题与快捷键打磨、配置迁移规则、安装/升级/卸载说明、已知限制、兼容矩阵、发布包与版本说明。

验收：

- 用户从发布包完成配置、启动、切换、通信、重连这一整条流程。
- 明确最低 Windows 版本、已验证架构、终端与目标 agent 版本；具体范围由实测确定。
- M0 关键路径在最终锁定的依赖和发布包上复验，不能仅沿用开发阶段或上游项目的结果。
- 核对发行物中的依赖、许可证与必要归属信息。
- 记录性能基线，检查持续输出和多会话情况下的输入响应。
- 发布说明区分已支持、实验性和不支持的能力。

对应需求：全量首版验收。

## 阶段调整规则

如 M0 证明选定来源耦合过重或后端无法覆盖必要命令，可以保留合适的视觉与交互，调整代码复用范围或后端实现；不得把未验证的复用比例、兼容性或性能作为承诺。改变已接受方向时创建替代 ADR，记录原因、影响的 FR/FL 编号与新证据，保留原决定历史。

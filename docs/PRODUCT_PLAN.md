# 产品计划

状态：产品计划 v0.3，M0 首批源码迁入已开始落地，完整产品与 Windows 验收尚未完成。更新日期：2026-11-21。初始规划基线：2026-11-20。

本文区分已确定的方向与仍待验证的行为。当前技术选型见[技术栈](TECH_STACK.md)、[决策记录](DECISIONS.md)及 [ADR](adr/README.md)，实施顺序见[路线图](ROADMAP.md)，能力状态与验收证据见 [Feature Ledger](FEATURE_LEDGER.md)。路线接受不代表功能完成或 Windows 兼容验收通过。

## 1. 定位

Agent Session Desk 是一个面向 Windows 的本地 CLI agent 会话工作台：用户提供启动命令，在统一 TUI 中管理多个运行中的会话，查看输出、发送输入，并让会话之间交换工作信息。

初版建议聚焦单个开发者在一台电脑上并行处理多个任务。团队共享、远程集群和账号体系暂不进入首版。

## 2. 要解决的问题

1. 多个终端窗口分散，会话难以命名、查找和组织。
2. 用户切换会话时容易丢失工作位置、草稿或对运行状态的判断。
3. 一些成熟 TUI 的会话后台依赖 Unix/tmux，无法直接满足 Windows 原生目标。
4. 会话之间传递结果依赖手动复制，难以关联请求、目标和回复。
5. 通用终端输出容易被误认为完整对话历史，输入写入容易被误认为任务完成。
6. 用户在其他会话工作时，不容易及时发现有 agent 在等待批准、回答或异常检查，只能反复巡查窗口。

## 3. 已确定的产品要求

- **Windows 原生优先**：核心流程不以 WSL 为前置条件。
- **CLI-first 与通用终端**：本地 agent、普通交互 shell 和 CLI 均可通过通用入口启动；使用终端原生输入区，不强制实现 ACP、HTTP 服务或专用 SDK。
- **支持自定义 agent**：用户可以配置自己的程序，不依赖预置品牌列表。
- **还原原有体验的多会话 TUI**：尽可能还原固定 Agent Deck 的布局、区域比例、交互、颜色和间距，以 Tab 为主要会话工作区，列表／搜索辅助组织；输入时保留 Tab 导航。样式通过 design tokens 管理，必要差异逐项说明。
- **控制运行资源**：优先减少常驻进程、重复输出缓存和非必要刷新，用真实进程树测量结果约束内存与响应。
- **跨会话读取与发送**：既支持用户操作，也为 agent 主动调用管理工具预留接口。
- **人工介入提醒**：以可靠状态标记待批准、待回答和待检查，提供统一待处理入口与可选 Windows 通知；已查看不等于已解决。
- **以真实 Windows 运行验证作为兼容依据**。

### 已记录的实现方向

采用 Go 1.27 与稳定 Charm v2 系列，选择性迁入 Agent Deck 的界面代码，并参考 Agent Manager 的 Windows 平台适配。上游使用 v1 的源码仅作来源与迁移参考；本项目具体依赖版本及迁移要求见[技术栈](TECH_STACK.md)与 [ADR-0005](adr/0005-dependency-lifecycle-and-upgrades.md)。

Windows 终端后台以 psmux 3.4.0 稳定发布为 M0 验证基线；Unix/tmux 路径后续扩展。配置使用 TOML，会话元数据和消息使用 SQLite，输出记录使用有上限、可轮转的文件；数据库驱动、后台 IPC 和数值资源预算仍待验证。

首版采用“创建／打开 Tab → 在 Tab 内操作终端 → 切换或关闭视图”。agent 与普通 shell／CLI 共用目标终端自身的输入区，不另加日常聊天输入框。全屏 attach 可保留为显式辅助模式。此方向由 [ADR-0014](adr/0014-upstream-ui-tabs-and-general-terminals.md) 部分替代此前列表主导航和内嵌交互后置决定；当前代码仍是旧路径，新 Tab 体验尚未实现／验收。现有 [v0.1 UI 图稿](UI_DESIGN.md)保留为探索记录，因界面过于杂乱，**不作为实现基线**。选择性复用的范围需要实际迁入确认，不承诺未经验证的复用比例。

## 4. 建议的初版用户故事

### US-01：开始一个任务

用户填写命令、工作目录和可选参数，创建名为“登录功能开发”的会话。界面显示启动过程、终端内容和启动失败原因。

### US-02：并行工作

用户创建“开发”和“评审”两个会话，在各自 Tab 内直接操作原 CLI，也可打开普通 shell Tab 执行命令；通过 Tab 导航切换，无需先 detach 回列表。切换不会重新启动程序；正在编辑的输入、输出滚动位置和当前焦点有明确行为。

### US-03：传递工作信息

用户选择开发会话的一段输出，附带来源后发给评审会话。管理器显示消息处于排队、输入已写入或后续可确认的阶段。

### US-04：Agent 主动协作

具备命令执行工具的 agent 通过拟议的管理 CLI 查询会话、读取输出、发送请求、查询回执。它需要可访问的控制接口和使用说明；仅启动一个 CLI 不会自动赋予该 agent 工具调用能力。

### US-05：离开后返回

用户退出 TUI，psmux 终端后台继续托管运行实例；重新打开后连接原实例。若 agent 已退出，界面保留历史并明确显示退出，不能因 shell 或终端后台仍存在而伪装成 agent 仍在运行。

M0–M2 不强制启动本产品自己的常驻 Host。M3 启用后台自动投递或持续提醒时，由一个共享轻量 Host 承担相应消费者；没有消费者运行时，消息可以落盘保留，但不会自动推进，也不保证持续监测人工介入。Agent 主动调用管理 CLI、后台消息消费与后台提醒分别实现和验收。

### US-06：知道哪个会话正在等我

用户正在会话 A 中输入，会话 B 通过可靠事件请求批准。B 在管理器中出现“待批准”标记，统一待处理入口增加该事项；启用桌面通知后，可在全屏 attach 或使用其他应用时收到提示，当前输入焦点不变。用户选择查看后定位 B；仅看过、关闭横幅或选择稍后提醒不会把问题标为已解决，只有对应处理证据才结束交互请求。

未知 CLI 不承诺准确识别，终端提示识别只显示疑似。已退出 Run 的审批/问答失效，异常待检查记录仍可查看并由用户显式标记已检查。M2 验证管理器运行时的接收与通知，M3 验证共享 Host 在 UI 关闭后的持续处理；无消费者的空档必须可见。完整规则见 [ADR-0006](adr/0006-human-attention-and-notifications.md)。

## 5. 共同业务词汇

| 对象 | 定义 |
| --- | --- |
| AgentProfile | 启动模板：命令、参数、默认环境、可选适配器 |
| Workspace | 工作目录和项目归属；是否独立工作目录需明确 |
| Session | 稳定的会话身份，关联名称、工作区、运行记录、输出和消息 |
| Run | 一次启动及其进程树；再次启动产生新的 run_id |
| Tab / View | 展示会话的入口，不承担会话身份 |
| Message | 一次请求或回复，具有来源、目标、编号和投递状态 |
| Task | 用户希望完成的目标，可能涉及多条消息、多次运行 |
| Capability | 某个接入实际支持的能力，例如 read_output、ready_signal、resume |
| AttentionItem | 绑定 Session/Run 与独立请求身份的待批准、待回答或待检查事项；生命周期、已查看/稍后提醒、观测新鲜度和通知投递结果分别记录 |

同一启动模板可以创建多个 Session。Session 可以经历多次 Run。Tab 的重命名、排序和关闭不改变 session_id。

## 6. 首版需求与验收

以下需求编号及原验收内容保持稳定。已接受的技术和交互方向按 ADR 实施；仍待决定的行为在对应决策明确后成为实施约束。已有 M0 局部实现；各能力仍未完成验收，具体阶段与证据以 Feature Ledger 为准。

| 编号 | 需求 | 可验收条件 |
| --- | --- | --- |
| FR-01 | 自定义 CLI 启动 | agent、普通交互 shell 和 CLI 均经命令、参数、cwd、env 配置启动；包含空格的可执行文件路径和工作目录按测试用例正确处理；错误可定位 |
| FR-02 | 原生终端显示和输入 | 在活动 Tab 使用目标程序的原生输入区，普通 shell 可连续执行命令；Windows 实机验证中文、Unicode、颜色、光标、窗口缩放、多行粘贴、滚动与交互式 TUI |
| FR-03 | 多会话管理 | Tab 承担主要会话入口，列表／分组／搜索辅助；尽可能还原上游布局比例、配色和交互，必要差异经评审；新建、命名、切换、停止和归档有明确入口；切换不会重启进程或发错输入 |
| FR-04 | 稳定身份 | 重命名和调整 Tab 顺序后，消息仍发到原 session_id 对应的会话 |
| FR-05 | 后台托管与重连 | 关闭 TUI 后，后台存活期间任务继续；重开连接原 run_id；后台或 agent 退出时显示真实状态 |
| FR-06 | 带来源的输出读取 | 读取结果含来源会话、运行实例与输出范围/游标；区分屏幕快照、输出日志和结构化消息 |
| FR-07 | 跨会话投递 | 请求生成消息编号；提供输入写入结果；没有接收或完成证据时，不显示对应成功状态 |
| FR-08 | 按能力排队 | 在具备可靠 ready/busy 信号的测试接入中自动等候并提交；未知 CLI 保留未知状态与显式投递能力 |
| FR-09 | Agent 控制 CLI | 支持执行命令的测试 agent 可调用 list/read/send/status；返回结果能进入该 agent 的实际工具上下文 |
| FR-10 | 历史与恢复边界 | 保存记录、接回存活实例、重启进程、恢复原对话分别可识别；未提供 resume 能力时明确说明 |
| FR-11 | 焦点与草稿 | 管理器快捷键和子终端按键不串用；切换 Tab 后保留管理器维护的未提交草稿和子终端原生未提交输入；输入不串会话，不被覆盖 |
| FR-12 | 异常与重复处理 | 启动失败、目标退出、后台断开、投递结果未知均可见；同一发送请求重试不会重复建立收件项；目标重启后旧消息不自动投递到新 Run |
| FR-13 | 请求与回复关联 | 合作式测试 agent B 对 A 的请求返回关联回复；A 能按消息编号查询结果，结果返回与任务通过验收分别表达 |
| FR-14 | 人工介入提醒 | 可靠事件触发原因标记与统一待处理入口；可选 Windows 通知在另一会话 attach 时不破坏画面/焦点/输入。事项绑定 Session/Run/请求身份，已读或稍后不解决，重复/迟到/旧 Run 不误触发或误定位；审批期间普通消息不自动提交。通知失败仍可查应用内事项；UI 退出后的持续提醒必须由已运行消费者或经验证 hook 提供，并单独验收 |

FR-08 的自动投递不得以“几秒没有新输出”作为唯一完成证据，也不能因 M0–M2 暂无自有 Host 而从产品范围删除。M3 需分别验证可靠信号下的自动投递、未知 CLI 的显式投递，以及关闭 TUI 后后台消费者的行为。FR-12 不承诺任意外部 CLI 的 exactly-once 执行；无法确认是否执行时保留不确定状态。

FR-14 补充人工介入体验，不把 needs_attention 当作 ready、任务完成或批准授权。通知点击只导航并核对目标；自动批准和从系统通知提交答案不进入本轮范围。断连保留不确定，真实退出使原交互请求失效；绑定结束 Run 的异常检查事项可继续保留。系统通知被接受不表示横幅已展示或用户已读，精确 Windows 接入、事件合同与数值预算按 ADR-0006 及测试待决项实施。

## 7. 建议的生命周期行为

| 操作 | 建议行为 |
| --- | --- |
| 关闭 Tab | 关闭视图，保留会话与运行实例 |
| 退出 TUI | 断开客户端，psmux 继续托管终端；消息是否自动消费取决于已启用的后台消费者 |
| 停止 | 结束明确选中的 Run，保留记录 |
| 重新连接 | 接回仍存活的 Run |
| 重新启动 | 创建新 Run，不声称自动续接模型上下文 |
| 恢复对话 | 通过已验证适配调用 agent 自身恢复能力 |
| 归档 | 收纳历史；运行中的会话如何归档需在交互设计中确定 |
| 删除 | 单独定义记录、日志和运行实例的处理范围 |

其中终端后台托管、全屏 attach 与 Run 身份规则按 ADR 执行；归档、删除等仍未确定的细节继续按 DECISIONS 跟踪。关闭视图不等于停止 Run，保存队列不等于已经自动投递。

## 8. 首版质量标准

- **视觉与交互**：会话身份、状态、输入焦点清楚；正文区域充分；以 Tab 主导航为本产品适配，尽可能还原上游布局比例、配色、弹窗、键鼠与焦点交互；必要差异可核对，主题和间距一致，主要操作可通过键盘完成。
- **Windows 兼容**：记录实际 Windows 构建、终端、字体、输入法、shell 与 agent 版本，不以 Linux 构建或示意图代替实机验证。
- **性能**：先记录 0、1、5、10 个会话在空闲与持续输出时的基线；分别计量管理器、psmux、控制台/shell 和 agent，关闭本产品非必要预热，限制缓存并轮转输出文件；数值门槛在 M0 实测后确定。
- **状态可信**：区分已确认、推测和未知；终端后台或 shell 存活不证明 agent 仍存活，agent 存活也不等于正在思考。
- **提醒克制**：只在需要用户关注的事项变化时提醒，同事件不反复刷屏；待处理入口常可查询，桌面通知、声音和完成通知默认关闭、按需启用；已有事件保存与系统通知结果分别表达。
- **可诊断**：出错时提供可定位的错误与脱敏日志；不把本地密钥、环境变量值或用户会话内容写入公共问题报告。
- **本地优先**：首版的会话控制与记录存放在本机；agent 自身访问模型服务的行为由该 agent 决定。

## 9. 首版暂不纳入

- 模型推理引擎、模型供应商计费和统一账号系统。
- 任意外部终端中已有进程的无缝迁入。
- 任意 CLI 都具备精确思考状态、完整结构化历史或中途 steering。
- 电脑重启后恢复活进程与未完成工具执行。
- 复杂自动编排、自动广播循环和多用户权限平台。
- 自动管理 Git worktree、自动合并并行修改；先支持明确选择工作目录。
- 独立开发另一套终端进程托管引擎；Tab 内交互已按 ADR-0014 纳入首版，具体屏幕模型与输入集成仍需验证。
- 为每个会话增加本产品自己的常驻协调服务，或同时再实现一套 ConPTY 托管层。

## 10. 首版成功的判断

用户能够用自己的 CLI agent 完成一条真实工作流程：启动两个会话、方便地切换、保留输入、传递相关输出、确认投递结果，并在退出界面后接回存活任务。界面质感与操作便利性一并进入验收。

对声明支持人工介入信号的接入，还应验证“在 A 工作 → B 请求批准 → 收到提醒并定位 B → 查看仍待处理 → 真正处理后结束事项”；原生通知、UI 关闭后的监测与通用未知 CLI 降级分别给出证据。

# ADR-0025：同组会话行的持久手动排序

- 日期：2026-11-24
- 状态：已接受，落实用户的上游体验还原要求；实现／验收另记
- 关联：FR-03/04/10/11/12；FL-003/004/005/011/012/013/018/019
- 扩展 ADR-0009/0012/0016/0023；不改变 Tab 排序或终端所有权

## 背景与决定

固定 Agent Deck `80494e527393b7ead00da30018e6ee7e60e9d7a0` 的 home.go 将 Shift/Ctrl+↑↓、K/J、+/- 分派给所选组或会话。groups.go 的 MoveSessionUp/Down 交换同组视觉兄弟并归一化位置，边界不跨组，跨组移动仍用 M。本产品没有来源的父子 Session／归档分区，不能凭空建立这些身份或将 Tab 顺序当成会话列表顺序。

1. 管理焦点下，会话行使用相同键与同组上一／下一行交换，跳过其他组；组标题保留原同父组排序。终端焦点所有同名键仍交给原程序。选择跟随原完整 Session/Run，活动 Tab、View 顺序、连接和草稿不变。
2. SQLite v5 追加独立 `session_positions`，按 scope/Session 保存所属 Group ID、非负 ordinal 和正 revision；名称／启动快照／Run／成员版本不作位置。未手动排序的旧组继续按名称／ID；首次移动按当前发现的同组行归一化后交换，显式写入这些行的位置。新会话或移入成员排在已有手动位置之后，其间按名称／ID 排序。历史行不加入当前排序集合，已保存的逻辑 Session 位置仍随元数据备份保留；历史页仍按 Run 时间查询。
3. 分组视图按各组的位置展示；平铺沿既有名称／ID 生成跨组槽位，再在同组槽位应用该组手动顺序，因此跨组行不被一次同组排序移动。组折叠与临时揭示不改变位置。移组清除该 Session 的旧位置（成员版本仍递增以识别 ABA）；删除组时旧组位置随受约束外键删除，收纳成员排在默认组已定位成员之后。不保留无界位置操作日志。
4. Manager 先重新发现并记录真实终端，再核对调用方完整有序同组快照。每次读取以流式摘要保存该组全部逻辑成员及 Run／停止事实、名称／成员／位置版本，Workspace 携带按组摘要；不在 UI 复制历史正文。Store 在一个写事务内重验摘要和同组集合、Session/Run/backend/command、名称／成员／位置及各版本；终端状态／pane 观测变化不作为排序冲突。邻居退出、加入、替换、改名影响顺序、成员变化、旧版本和 ABA 均拒绝。元数据与后端发现不具有跨资源原子性，不能把已存 Run 当作实时在线证据。
5. 成功写入移动双方及位置确实改变的其他当前行，增加对应位置版本；初次位置版本为 1。边界无写入；任一待写入版本耗尽或 SQL 故障整体回滚。未知提交结果显示错误并要求刷新，不自动重试或乐观保留未保存顺序。
6. UI 与组排序互斥，一次只接受一笔，不堆积旧快照；终端事件、Tab 切换继续处理。晚到回执只向仍存在且完整原 Run／成员／名称版本匹配的行合并位置，不添加或复活会话。提交前发现失效，随后按需重查。正常管理退出等待已接受排序结果，再遵守输入／偏好退出屏障；失败取消此次退出，保留错误。
7. v1–v4 在同一初始化事务升级到 v5，冲突回滚；只读 check／backup／restore 继续识别 v1–v5，检查位置结构、约束和当前成员一致性。ui.toml 仍 v3，输出不纳入数据库备份。旧程序拒绝未知 v5，不直接回退打开；上线前需要实际迁移、并发、恢复和 Windows 验证。

## 取舍与验证

不使用 Tab 顺序、后端标签或 ui.toml 中的有界 ID 字符串替代逻辑 Session 排序；独立位置表避免重写启动事实。与来源同步 forceSave 相比，本产品异步 CAS／错误和退出屏障是明确适配。平铺槽位与来源没有相同产品模型，单列记录，不宣称完整上游一致。

必须验证同组交换、边界／无效快照无写入、外组不变、刷新／重开、移组／收纳、ABA／并发／故障回滚、v4 迁移／只读检查／备份恢复，以及排序期间终端键、活动 Tab、原草稿和退出。来源文件／哈希和许可沿复用清单记录；决策接受不代表实现或 Windows／整体视觉已接受。

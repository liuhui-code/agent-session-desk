# ADR-0034：配置化页脚模式与通用终端提示

- 日期：2026-11-24
- 状态：已接受还原范围内的实施决定；平台验收另记
- 关联：FR-03/11/12；FL-003/012/013/016/018/019；ADR-0014/0017/0032/0033

## 决定

1. 接固定 Agent Deck `80494e527393b7ead00da30018e6ee7e60e9d7a0` 的四种 footer 配置：full 为原默认宽度自适应，compact 强制无填充键块与说明，minimal 强制仅键，curated 为暗色文字的少量上下文提示。均在小于 50 列退到既有窄窗提示；不改变框／行带高度。
2. 同来源采用配置入口，不新增来源没有的设置行。ui.toml v7 新增可选 footer；缺省／空／未知值回退 full，已知值忽略首尾空白与大小写。内部零值保留缺省，显式保存省略零值；有值时规范化。旧 v1–v6 只读加载，显式保存升级；旧版本夹带 footer、坏类型／未来版本拒绝，旧 max-v6 读写拒绝 v7 单列验证。
3. curated 的上下文最多三项，按优先级从尾部裁掉，保留最后 S 设置／? 帮助；文字为暗色、键加粗、两个空格分隔。不展示本产品没有的重启、fork、队列或 agent 状态。通用会话显示实际可连接的 Enter／新建／改名，组用 Tab 展开折叠／新建／改名；不可连接会话不显示 Enter。默认 full 的退出锚点与既有行为继续保留。
4. 这四种模式只改变管理焦点页脚；终端焦点下保留黄色模式／原目标与 F6 提示，不能让配置掩盖输入归属。所有模式只是显示，不新增按键路由、终端输入、启动／停止、进程或背景刷新。
5. 颜色、粗细、间距、装饰与响应式边界继续由 design_tokens.go 管理。选项随整份界面偏好保存，修改主题／密度／导航／比例时保留 footer；不保存到启动模板或 SQLite。不提供配置热重载，与来源初始化读取一致。

## 验证

先验证配置保存／旧读写边界，再验证真实 Model 的模式选择、颜色角色、上下文、缩放、设置保存保留与终端输入归属；固定源模式／样式对照、模型、Windows 原生及桌面视觉分别留证。来源 RGB 或 Go 模型通过不等于完整上游体验／发布接受。

后续：[ADR-0035](0035-pinned-source-display-colors.md) 保留作者色值，并在 token 显示副本中校正固定来源两个 TrueColor 角色；前轮三组输出差异已有独立本地复验，原报告／平台范围不改写。

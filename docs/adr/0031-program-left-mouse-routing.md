# ADR-0031：声明鼠标的目标程序左键输入

- 日期：2026-11-24
- 状态：已接受方向；实际平台验收另记
- 关联：FR-02/03/04/11；FL-002/003/005/012/013/016/018/019
- 扩展 ADR-0029/0030；程序手势的有界释放细化 0029 第 5 项，原生选区取消仍不合成释放

## 决定

1. 已连接、终端焦点、非复制模式且最新帧声明 WantsMouse 时，无修饰左按／左拖／左释放交给原 pane 的既有 pane-mouse 协议，不进入产品复制模式，不转换为文字／方向键。右／中键、修饰、悬停与完整程序兼容继续开放。
2. 一个 UI 同时只持有一个程序左键手势，绑定原连接代次、内容矩形及屏幕尺寸。起点必须位于可见内容；越过框、Tab、列表后的运动／释放仍由原手势消费，坐标夹到原 pane 的可见内容内，不变成管理操作。第一次管理焦点点击仍只聚焦；重复按下／释放不重发。
3. 通过既有 FIFO 排在已接受输入之后。程序按下被接受后，最多使用队列容量减一，保留一个原目标释放位置；过量拖动明确拒绝，不重试，释放仍可入队。保留位置是传输防御，不是资源预算。
4. 键盘／粘贴／滚轮、主动切 Tab／管理视图或 resize 前，在原连接上以最后接受坐标入队一次左释放，再处理后续动作；本地手势立即清除，释放不重试。此为程序按住状态的结束操作，不是点击／批准／Enter，不读取剪贴板。原生复制选区仍沿 0029/0030 取消而不合成复制。
5. 无按钮运动或不支持的修饰运动结束已持有的程序手势；外部帧的模式／鼠标声明／几何变化、连接失效或身份变化只清除本地所有权，不把释放转投别的模式或 Run，结果保留未知并提示核对。已接受写入不证明程序处理，外部模式竞争仍没有锁。
6. 程序鼠标与直接拖选由已观察模式分工：CopyMode 优先原生选区；实时 WantsMouse 使用程序手势；实时未声明鼠标使用 0030 的原锚点交接。原 pane、后端终端所有权和无新聊天输入框不变；依赖、tokens、历史和存储不变。

## 验证边界

本地验证原 pane 的协议、内容坐标、队列／保留释放、重复事件、原队列排空后切换及未知模式不转投。固定 psmux 的 VT／Win32 注入策略和按住按钮状态须真实程序独立验证，Go 模型不能证明它们。Windows 上传授权未解决期间不绕过；完整上游鼠标、实体输入、agent 和发布仍分别验收。

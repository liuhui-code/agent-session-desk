# ADR-0036：按框架颜色能力还原显示索引

- 日期：2026-11-24
- 状态：已接受还原范围内的实施决定；平台和整帧验收另记
- 关联：FR-03/11；FL-003/012/016/018/019；ADR-0005/0014/0032/0035

## 决定

1. 继续使用锁定 v2 框架，通过 ColorProfileMsg 接收实际颜色能力，不新增检测器、环境扫描、背景查询或轮询。未知能力暂用既有 TrueColor 样式；仅接受已知能力值，重复通知无额外动作。
2. 作者 tokens 不变；显示副本依据固定来源真实渲染器的测量数据，对 20 个已用主题角色及两个索引辅助色选择 ANSI／ANSI256 的来源调色板索引。TrueColor 保留 ADR-0035；不复制旧转换库，不将其他任意颜色纳入旧库模拟。
3. ASCII／NoTTY 的管理样式去掉颜色、加粗、斜体和下划线，与来源无色显示一致；边框字符、布局、键位、选择标记和 Tab 归属继续保留。原终端屏幕属性不被重写，最终框架按终端能力输出；该能力不等于任意真实程序已验收。
4. 默认前／背景请求只在框架确认 TrueColor 后使用既有作者默认色机制；未知、ANSI、ANSI256、ASCII／NoTTY 不请求 RGB 默认色，初始有限能力沿来源不改用户默认色。TrueColor 后的能力切换仅交由既有 v2 View 机制发出复位，不声称恢复用户此前运行时改色；释放旧请求，不增加系统设置写入或新 OS API；真实终端恢复继续独立验证。
5. 能力事件先于模态输入处理，仅重建样式并保留表单值、位置和焦点，不保存偏好、断开终端、切 Run 或注入输入。主题／System 变化沿当前能力重建显示副本，能力不写 ui.toml。
6. 将已有 colorprofile v0.4.3 声明为直接依赖以使用框架事件类型；模块集合／版本不变。ui.toml 仍 v7，SQLite 仍 v5。全部显示数据、布尔样式和边界仍由 design_tokens.go 定义，styles.go 只组合。

## 验证

来源与产品的真实 Tea 渲染器均禁用输入、只输出到内存，比较四能力下的 24 颜色／6 组合（每种 30 项）和正常退出。先保存差异与模型 RED，再验证能力事件、往返／模态状态、默认色请求、原终端属性、有限布局和所需常规检查。只证明固定合成角色与指定框架组合，不以此关闭真实终端的调色板／默认色恢复、Windows、完整字体／交互或发布验收。

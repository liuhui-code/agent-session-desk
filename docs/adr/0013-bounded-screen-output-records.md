## 决定

`asd record SESSION_ID` 对实时发现并重验的原目标调用既有 Preview，保存一次最多 200 行／64 KiB 文本的屏幕快照。已退出但仍保留原 pane 的目标可按后端既有合同捕获；已停止或消失的目标不能借历史重新启动。管理器自动预览不写这些文件，不增加后台轮询、包装进程或 Host。

`asd output RUN_ID` 从当前元数据作用域读取该 Run 保留的快照，不依赖后端程序存在。结果含独立 record_id、Session/Run/backend、采集时刻、保留序号、文本、truncated，以及固定 source=screen_snapshot、complete=false。没有记录只表示没有保留的捕获，不证明期间没有输出。原始终端控制符作为 JSON 字符串数据保存，CLI 默认通过 JSON 转义返回；不把记录正文直接重放为终端控制。

这是 M1 的最小输出记录，不是连续 stdout／PTY 全流日志、原生对话、模型上下文、M3 输出游标或任务回执。即使 truncated=false，也不证明该 Run 从启动以来的输出完整。采集时刻不是进程退出时刻，读取不推断当前状态。

## 文件与工程边界

输出位于 metadata.sqlite3 同目录的 output-records，SQL 不保存正文、不新增 schema。目录必须有精确 .format 标记；已有未识别目录、未知文件、链接／junction、畸形或过大文件拒绝，保留其内容。记录文件名由随机 record_id 派生，字段和原元数据核对，不从输入正文拼接路径。

固定工程上限：每份文本 64 KiB、每文件 512 KiB、每个 scope/Run 最多 2 份、每个数据库目录总共最多 32 份已发布文件，最多 1 份暂存。已发布文件逻辑字节之和最多 16 MiB，暂存最多 512 KiB，另有格式标记；这不是磁盘实际分配、全部数据目录、SQLite 规模或产品进程资源预算。非法 UTF-8 先规范化，超长内容保留完整 UTF-8 边界上的尾部并标明截断。

读取目录条目和单文件内容都按上限读取，不能先读入无限内容再拒绝。按 retained sequence 排序，不以墙钟猜测先后；新值取当前保留记录的最大值加一，不承诺轮转后仍有完整终身序列。record_id 才是记录身份。

## 并发、落盘与失败

捕获先完成，再取得现有 SQLite BEGIN IMMEDIATE 事务用于同库、跨入口／作用域的文件操作仲裁；不跨后端调用持锁。事务不写正文或持久的新表，退出时释放。读取同样取得该锁以避免与轮转拼接不同文件；busy/cancel 明确返回，不能报保存成功。

生成保留名字空间中的暂存文件，写入、Sync、Close 后才轮转；先收至每 Run／全局上限，再通过同目录硬链接非覆盖发布完整 JSON。读者不能看到半份正式记录；不支持硬链接时明确失败。正常失败清理自有暂存。成功发布后临时清理若失败，返回具体 record_id 与“已发布、清理失败”，不把捕获成功和落盘成功混为一谈。

持有数据库锁的后续写入可清理保留名字空间内的遗留暂存；这利用强杀会释放数据库锁的事实，不根据 PID 猜测另一个写入者是否存活。不跟随链接清理外部目标，不删除未知文件。

文件轮转与发布不是 SQL 原子事务：若部分旧捕获已删除而发布失败，报告未发布及可能轮转，保留元数据和终端运行；没有完整日志承诺。强杀可能留下未发布暂存，后续读取跳过它。数据库备份恢复继续仅覆盖元数据，不暗示这些输出文件已备份；完整档案与备份包属于后续工作。

## 验证范围

逐行为 TDD 验证重开、UTF-8、跨 scope/Run、每 Run／全局轮转、正式文件可见性、未知／过大／更强状态文件拒绝、并发写入与遗留暂存。原生 Windows 用真实 psmux/fixture 验证配置命令／目录、三次捕获保留两份、目录归属和 NTFS junction 拒绝、停止后的离线读取；精确结果以执行报告为准，不以交叉编译或此 ADR 的状态替代。

未实现连续输出流录制、磁盘满的完整故障注入、日志归档／搜索、原生对话恢复；不凭手工捕获推断 agent 任务状态。真实 agent 兼容与完整 Windows／发布门槛继续分别记账。

# ADR-0069：显式恢复中心与原启动复用

2026-11-28，已接受并实施。关联 FL-001／002／011／013／018；细化 ADR-0016／0063／0064。数据库保持 v11，声明／结果协议保持 v1。

管理模式大写 R 打开恢复中心，按需读取最近 100 条作用域内历史，再按逻辑 Session 去重；不声称完整历史检索。h 继续只读。详情在同一只读事务中读取最新 Run、恢复声明、尝试和完整启动快照；不调用终端、不启动进程。面板保留健康原客户端，消费键盘／粘贴／鼠标；迟到读取不重开已关闭面板。没有新增常驻进程、监听或周期查询。

三个动作明确分开：

- a 仅接回当前发现中身份完全一致且可交互的原终端；原生输入繁忙／切换中或发现失败时拒绝，不自动重启。
- n 将完整原启动描述填进既有 New terminal 表单，保留参数数组边界和环境覆盖，用户再次提交才创建全新逻辑 Session。缺失快照不猜补；含 ASD_RECOVERY_ 的旧交接启动拒绝克隆，避免复用旧凭据。
- r 仅在有效 Agent 声明、已完成发现且原终端不存在时打开恢复确认。原终端包括保留的退出画面；需要用户先按现有显式停止流程处理。缺席不是死亡证明，表单额外要求用户确认旧 Run 已结束。默认 Cancel；Space 勾选、Tab 选择 Start recovery、Enter 仅启动一次。过窄／过低窗口禁止启动并撤销勾选，需放大重新确认。确认时 a／n 不跳过表单。

启动桥接复用 Manager.Recover 的新 Run／新凭据、最新 Run／声明修订复核、后端再发现和 CAS 预留。不自动停止、批准、重发输入或回落成新对话。进入 Recover 后错误按不确定结果处理，禁止盲目重试；launch_unknown 在持久元数据中仍阻止重试。单纯 started 不显示 restored，只有既有认证结果合同可确认 Agent 自报恢复。

每次恢复上下文为元数据目录下最多 32 个固定 recovery-context-NN 私有目录，独占创建，不覆盖、重用或自动清理 Agent 可能持有的路径。满额要求人工检查旧尝试再清理。并发创建／部分准备失败可见且不自动换身份重试。凭据、声明、启动详情和终端正文不进入 ADR-0068 的可分享诊断。

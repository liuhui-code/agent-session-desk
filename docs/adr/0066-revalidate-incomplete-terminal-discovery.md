# ADR-0066：漏列原目标复验与活动连接独立存活

2026-11-27，已接受。细化 ADR-0016／0057／0062；关联 FL-001／012／015／018／020。

## 原因

用户反馈从最小化恢复后列表、蓝点、终端和桌宠同步变化。实际 Windows 隔离诊断捕获：psmux 成功返回的全局枚举临时从两条变成一条，下一轮恢复；UI 将缺席视为不可交互，关闭仍正常的活动客户端并留下不可自动恢复的错误。此轮无五秒超时或尺寸风暴；四种表现的完整用户现场并未全部复现。

## 决定

- psmux Backend 进程内只保留最近成功发现的至多 128 条原始身份提示；不持久化、不保存屏幕、不代表存活或控制授权。条目受现有 4096 字节元数据上限限制，不是整机资源接受预算。普通全量发现不增加查询；仅当已知名称漏列时按确定顺序直接查询原名称。
- 补查必须重新解码并匹配完整 liveRecord，包括 Session／Run／原 pane；随后仍执行原 pane 身份与状态／程序观测。不能将旧 Available 当成本轮事实，也不改变 attach、输入、PID/FILETIME/path 或原 pane 防回退检查。
- 补查失败或身份变化使当前发现保持未知，并淘汰该提示，避免永久保留不可验证目标；后续枚举可以移除该行，不伪造退出事件。显式 Stop 成功与确认无 server 清除对应提示。并发访问串行保护，沿用现有请求截止时间。
- 活动客户端已连接或正在连接时，仅列表缺席不主动关闭它；终端自身的身份核验、流错误和明确的原 pane 退出仍按原错误路径处理。不自动重启、不重放输入、不额外连接。无客户端的失效 Tab 仍受原重连检查约束。
- 不改变轮询、活动鲜度或桌宠提醒语义；真正发现错误仍显示未知，绝不以旧提醒声称授权／问题已经解决。

## 验证与限制

[实际报告](../testing/results/2026-11-27-idle-discovery.md)保留 RED、真实漏列前后轨迹和失败的观察器轮次。修复后四轮最小化／恢复再次出现漏列，但直接复验保留两条原会话和同一连接；诊断变体与正式构建分开记账。真实 Agent、所有宿主、长期资源和完整发布接受仍开放。数据库／配置 schema 不因本决定变更。

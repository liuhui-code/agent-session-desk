# ADR-0026：显式停止原 Session／Run

- 日期：2026-11-24
- 状态：已接受方向；实现和实际验证另记
- 需求：FR-02/03/04/10/11/12；能力：FL-002/004/005/006/011/012/013/018/019
- 扩展 ADR-0009/0014/0016；不改变后端进程所有权、历史与 agent 状态语义

## 决定

1. 管理焦点在 Session 行按 `d` 打开停止确认；组标题仍打开删除组。沿固定 Agent Deck `80494e527393b7ead00da30018e6ee7e60e9d7a0` 的确认框布局、红框、黄警告与默认取消交互，使用“停止”文案，明确会终止该终端及其程序、未保存工作可能丢失。`x` 仍只关闭 Tab；历史、输出记录、Session 名称及分组不删除，归档／删除历史另立合同。
2. 弹窗绑定所选 Session，而非当前活动 Tab。先排空已接受的原终端输入，再断开客户端。显示完整当前名称、程序、Session／Run 身份；窗口不能容纳完整审阅，或名称／程序超出既有有界显示入口而被截断时，不得确认。终端焦点的 `d/y/n` 保持原生输入，模态里的按键、粘贴、鼠标不穿透。
3. 默认 Enter 取消；←／h 选择停止，→／l／Tab 选择取消，Enter 执行所选项，y/Y 明确停止，n/N/Esc/Ctrl+C 取消。提交后单次执行，忙时不取消／退出；错误后只能返回刷新核对，不在同一个弹窗重试。
4. 确认时 Manager 重新发现并保存／投影 Workspace，严格比较原 Session ID、Run ID、Backend ID、Command、当前名称及名称版本；名称 ABA 也失效。缺失、重复、未知状态或变化时拒绝，不转投替代 Run。分组和排序与停止目标独立。保留后端临执行前的 Session／Run 标签复核；发现、SQLite、后端停止仍非原子事务，不声称跨资源 CAS 或消除后端自身的检查／执行间隙。
5. 已退出但后端保留的终端也可显式停止以释放托管容器；`unknown` 不可确认。只有后端 Stop 成功后才写既有 stopped_ns；缺失／断开不推断停止，停止确认不是 agent 完成或退出码。后端结果、超时或停止后元数据失败均保留明确错误，不自动重放。
6. 回执仅更新原完整目标的 Tab，保留已停止视图；不关闭其他 Tab，不覆盖替代 Run。成功使原目标不可输入，刷新列表并保留离线历史；取消重接原活动终端。异步旧列表失效，迟到回执以弹窗身份核对，失败不伪装成功。
7. 本切片不新增存储 schema、主题或样式数值；沿既有确认框 tokens。普通 shell 的实际原生验证与模型测试分别记录；完整桌面／IME、真实 agent、资源预算和发布仍单独验收。

## 来源与取舍

来源 ConfirmDeleteSession 会终止终端并移除注册记录，产品只复用确认交互，明确保留历史和逻辑身份，避免删除记录掩盖进程结果。完整身份比只看名称更严格；新鲜发现提高拒绝错误目标的能力，但不能证明之后外部状态不变。提交后的不确定结果要求核对，而非依据错误类别猜测可以安全重试。

实际实现、来源指纹、RED→GREEN、失败流程及 Windows 证据由 Feature Ledger 和独立执行报告记录。

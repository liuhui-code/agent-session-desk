# ADR-0018：原生选择／搜索与外层终端剪贴板

- 日期：2026-11-23
- 状态：已接受，落实 ADR-0014 的原终端体验；实际范围以执行报告为准
- 关联需求：FR-02、FR-03、FR-11；能力：FL-002、FL-003、FL-007、FL-012、FL-018、FL-019
- 部分替代：ADR-0016 第 6 项仅文字／SGR 的输出边界，新增下列受限结构化元数据；不允许原始 VT 穿透
- 实现与验证状态：[实际执行报告](../testing/results/2026-11-23-native-copy-search.md)单独记录；完整视觉、真实 agent 与发布未验收

## 背景

固定 Agent Deck 的内嵌终端允许终端自身的复制模式，并转发 OSC52 复制请求。现有产品已接原生历史滚动，但没有显式选择／搜索入口，忽略了选区、搜索命中、复制光标、搜索提示光标及剪贴板事件；只操作按键不足以还原可见体验。

psmux 3.4.0 的固定来源 `20aa1d7254ee93f64dafa059ef89341d9767470a` 已有相应协议。继续由后端维护历史、快照、选择及搜索，避免产品再建一份终端历史。产品保持稳定 Charm v2，未引入上游 VT 引擎、原生剪贴板新依赖或另一套 ConPTY。

## 决定

1. 支持此能力的活动连接在管理焦点 `v` 进入原生复制模式，使用指定原 pane 的 `copy-mode -t`，经既有 FIFO 排在已接受输入之后；随后焦点属于原生模式。终端中的字面 `v` 保持输入。复制模式的方向键、空格、Enter、`V`、`/`／`?`、Esc／q 等由固定后端解释，不另建聊天框、搜索历史数据库或按键状态机。新入口不会打开另一个 Run。
2. 可见屏幕之外的历史仍在 psmux；产品只保存最新屏幕、受验证的选区／光标／搜索命中元数据。选区支持字符、整行与矩形的原生几何；颜色及光标样式全部经 `design_tokens.go`，`styles.go` 组合，默认沿用固定原生复制模式的黑／黄、青／洋红／红等 ANSI 角色。自定义后端 mode-style 的完整传播仍待做，不隐含为主题设置已实现。
3. 搜索提示的 `status_label`／`status_cursor` 为 UTF-8 **字节偏移**，先验证范围、字符边界与无控制字符，再换算单元格；宽度不足时保留标签并滚动输入区，让光标及其附近文本可见。普通 Run 光标、复制光标、提示光标分别处理，不把隐藏的 live 光标重新显示成搜索位置。固定后端在 resize 的搜索提示期间可能保留旧视口复制光标；越界时隐藏该可选光标，保留已验证的画面与有效提示，选区／命中及 Session／pane 边界不放宽。
4. 从已认证且 Session／active leaf pane 与连接匹配的帧解析 `clipboard_osc52`。只接受非空、有效 Base64、UTF-8、无 NUL、解码后至多 64 KiB 的文本；原始 `?` 查询、空、错误或超限 payload 丢弃，不破坏正常屏幕。64 KiB 是防御边界，不是资源预算或完整输出上限。其他原始控制序列仍不直接执行。
5. 复制事件与屏幕合并通道分开；每个传输最多保留一个最新未读 payload。UI 使用稳定 v2 `SetClipboard` 发出外层终端 OSC52，只写 system selection，不查询或向 CLI 反馈用户剪贴板。当前活动 CLI 自身发起、且被后端按其剪贴板策略转发的有效复制请求也可走此路径；本轮只验证原生选择产生的事件，CLI 主动复制的策略与兼容另行保留。外层终端可按自身设置接受或拒绝。
6. UI 同时最多提交一个复制请求；发出请求至框架顺序确认期间，新 Tab 暂不启动剪贴板读取。完成后恢复当前连接的唯一读取器；确认令牌与实际在途请求匹配，旧事件／重复确认不能建立额外读取器或覆盖新目标。每个连接的读取随断开取消；关闭、隐藏／重开和异常后不自动重放不确定复制。
7. 界面只显示“已向终端发送复制请求”。框架成功写出 OSC52 不等于系统剪贴板已保存；实际兼容性必须用 Windows 桌面独立读取合成内容验证。没有原生助手进程、后台每 Session 剪贴板服务、原剪贴板读取或产品数据库写入。

## 边界与代价

clipboard 字段没有独立的原始 pane／program 身份，匹配帧只证明该受认证服务器的当前屏幕身份；不能把它当作 agent 来源认证、任务接收、结构化通信或完成证据。现有单 leaf／原 pane 约束保留，不因此支持任意外部服务器拓扑修改。

复制模式仍受单帧 2 MiB、防御尺寸和原生后端能力限制；连续历史、所有 Unicode／重排／鼠标选择、更多终端的 OSC52、资源预算与长稳需要继续验证。当前实现不提供复制失败后的自动 fallback／重试，不以静态画面等同实际剪贴板成功。

相比另建本地历史／搜索引擎，本方案复用原终端语义；代价是依赖固定协议、外层终端设置和后端复制模式的实际缺口。若稳定后端不能正确提供所需数据，须记录直接对照、源版本与新决策，不能静默换 master 或改托管所有权。

## 验证与依据

- 语义入口不得变成 shell 文字；原草稿、Tab 和 Session/Run 不改变，选择／搜索按键不执行命令。
- 验证 UTF-8 字节到单元格、中文／组合字符／emoji、窄窗提示、选区与命中优先级；无效元数据拒绝。
- 验证事件不因屏幕合并丢失、上限与无效编码、关闭取消、旧代次和跨 Tab 在途排序；实际事件循环输出与 Windows 剪贴板分别留证。
- 固定 [Agent Deck 内嵌终端](https://github.com/asheshgoplani/agent-deck/blob/80494e527393b7ead00da30018e6ee7e60e9d7a0/internal/ui/embedded_terminal.go)、[psmux 协议](https://github.com/psmux/psmux/blob/20aa1d7254ee93f64dafa059ef89341d9767470a/src/server/connection.rs)、[布局元数据](https://github.com/psmux/psmux/blob/20aa1d7254ee93f64dafa059ef89341d9767470a/src/layout.rs)、[复制模式](https://github.com/psmux/psmux/blob/20aa1d7254ee93f64dafa059ef89341d9767470a/src/copy_mode.rs)。源码仅核对语义与协议，Go 适配／事件桥自行实现，没有复制 Rust 实现。
- Context7 资料包含 beta／main；具体 API 再按锁定 Bubble Tea 2.1.2 与 x/ansi 0.11.9 源码和行为核对，未升级依赖。

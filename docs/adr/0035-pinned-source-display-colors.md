# ADR-0035：作者配色与固定来源显示值分离

- 日期：2026-11-24
- 状态：已接受还原范围内的实施决定；平台／整帧验收另记
- 关联：FR-03/11；FL-003/012/016/018/019；ADR-0014/0032/0034

## 决定

1. 保留固定 Agent Deck 作者 Dark／Light 的 20 个已用十六进制角色。固定来源实际 TrueColor 输出与作者值之间的截断差异，作为独立显示合同记录，不通过允许 RGB 容差关闭缺口。
2. 针对已用两套配色中实际不同的两个角色，在 design_tokens.go 明确记录来源显示映射：暗色 accent 的 #7aa2f7 → #79a2f7，亮色 dim 的 #6a6d7c → #696d7c。样式构造仅使用 tokens 的局部显示副本，Model 的作者 tokens 不变；其他已用角色不改。它是固定主题的测量数据适配，不是任意颜色的旧库模拟器或新的主题选项。
3. styles.go 仍只组合 token；继续使用稳定 v2，不引入 Lip Gloss v1／termenv 或复制其转换代码。两个映射来自实际隔离来源输出，源转换链与 MIT 许可只作为诊断参考记录。保留来源／产品色值、实际输出和修改前失败证据。
4. 仅管理 UI 样式使用显示副本。系统主题观测与显式主题切换都重新从作者配色构造；已有输入文字／焦点和原 Session/Run 不变。终端屏幕显式颜色、复制选择、默认终端颜色查询和输入链路不参与此适配。
5. ui.toml 仍 v7，SQLite 仍 v5，依赖不变。20 个角色与页脚 6 组可见样式的精确 TrueColor 对照单独验收；16／256 色降级、真实终端字体／桌面、系统恢复及完整视觉验收继续开放。保留早期差异报告，不将修复后结果回写为早期通过。

## 验证

先以真实 View 的两个差异角色建立 RED→GREEN，再执行两套完整角色与实际组合样式对照、主题往返／输入保留、布局回归及所需常规检查。作者色值一致、实际 RGB 输出一致和 Windows 完整接受分别留证。

# ADR-0047：Run 绑定凭据、请求查询与关联回复

- 日期：2026-11-26
- 状态：已接受，用户同意继续完成后端请求／回复闭环并要求接口文档
- 关联：FR-04/07/09/12/13，FL-005/008/010/013/014/019
- 扩展 ADR-0045/0046；不改变终端投递状态、前端或自动消费范围

## 决定

复用现有 CLI、SQLite 和事务约束。增加 `agent-bind`、`inbox`、`reply`、`replies`，不增加网络服务、Host 或前端操作。SQLite 事务迁移至 v7；v1–v6 保留原身份／消息／证据后升级，离线 check 与非覆盖快照支持新表。

来源采用显式委派的随机本地 capability：管理员用完整 Session/Run 绑定一个 256-bit 随机凭据，数据库只存 SHA-256 摘要。凭据文件在显式目录以完整暂存、同步、同目录硬链接发布，不覆盖已有文件；同一文件／绑定可重试，不能隐式轮换。文件先完整发布，后提交绑定；绑定结果不明时保留原文件继续核对，避免丢失已提交绑定的凭据。文件、快照和 SQLite 不是跨资源原子事务。

接收方用 `--token-file` 调用 inbox／reply，不接受可任填的 --from。凭据核对 scope、Session/Run 后，每次重新发现原 backend_id／command 和终端状态；提交时 SQL 再拒绝已记录停止或 pane 退出的 Run。凭据不进入终端正文、公开 JSON 或命令行参数值。只声明持有者对该原 Run 的本地委派，不声称识别真实 agent 程序、隔离同一用户或防止有数据库写权限的本机控制者。源端退出与 SQL 不是原子事件；已发生但尚未被观察的退出不能被凭空识别。

inbox 返回该 Run 尚无回复的请求，最多 128 条，created_at／ID 升序，不投递、不领取任务。包括 queued／unknown／input_written，状态必须保留；它不是可以无条件自动执行的队列。接入方选择明确的任务接收路径；unknown 需要核对，不能通过再处理制造重复副作用。终端输入消费与读取元数据分别表达。

每条请求先支持一份显式结果。reply 使用稳定 reply_id 和 reply_to，来源必须匹配原消息 Target 的 Session/Run/backend_id/command。事务内核对授权、原消息、回复 ID 和单结果约束：同 ID／同来源／同父请求／同正文返回原结果与时间；冲突或第二个结果明确拒绝，不覆盖。回复保存来源快照、正文和记录时间，不把它变成 accepted/completed 或用户验收。原消息的 queued／unknown／input_written 不变。

replies 通过原 message_id 离线读取 [] 或一条结果，源 Run 退出后仍可查；新提交及重试提交均需原 Run 通过重验。回复领取／保存不调用终端 Paste/Start/Stop。没有回复订阅、进度聚合、回复撤销或自动通知。

## 边界与文档

沿用正文 64 KiB、序列化记录 512 KiB、同库全部作用域合计 128 条请求。每请求一结果与外键使回复数量不超过请求数量。绑定同库最多 128 条、每 Run 一条，不自动清理；保留幂等与来源证据。原凭据丢失时当前不提供轮换／恢复密钥，新 Run 需新绑定。Windows 文件权限继承目标目录策略，不能将 Unix 0600 当作 Windows 独立 ACL 隔离证明；凭据目录由调用方保护。

接口参考统一维护在 [AGENT_API.md](../AGENT_API.md)，包括命令、JSON、幂等、错误／超时恢复和可执行步骤。当前 `api_version` 仍未加入；消费者固定构建，schema v7 不是公共协议版本。升级真实数据前备份；本轮使用隔离测试状态，不迁移日常安装。

依据 Context7 查询的 SQLite 官方[复合外键](https://www.sqlite.org/foreignkeys.html)、既有立即写事务／唯一约束和本项目持久 outbox；未新增依赖或复用外部实现代码。验证见[实际报告](../testing/results/2026-11-26-structured-replies.md)。真实模型 agent、完整自动消费、共享 Host、UI／资源长稳和发布接受保持开放。

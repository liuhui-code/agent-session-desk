# ADR-0033：有界系统主题观察与显示配色分离

- 日期：2026-11-24
- 状态：已接受方向；实际平台验收另记
- 关联：FR-03/11/12；FL-003/012/013/015/016/018/019
- 扩展 ADR-0032 的 System 选项与 ui.toml 版本；不改变终端／历史／Host 所有权

## 决定

1. ui.toml v6 接受 theme=system，保存选择而非观测到的 dark/light。v1–v5 只读载入，显式保存升级；v5 仍拒绝 system，未来版本／坏值拒绝。旧版读写对 v6 的拒绝另证。
2. 沿固定来源 ResolveTheme 的终端声明优先意图：合法 COLORFGBG 的最后完整整数 0–7 为 Dark、8–15 为 Light；其他值无可靠声明。Windows 无声明时，用既有 x/sys v0.49.0 只读观察当前用户 AppsUseLightTheme（DWORD 0/1）及其变更通知。无可靠检测时保留最后成功配色，首次暂用 Dark，并明确未知。非 Windows 只接终端声明，原生 OS 检测继续开放。
3. 有声明时不建立 OS 观察器，持续跟随该进程固定声明；不同于来源初始化读取终端声明、随后 OS watcher 可能覆盖它的组合。此为明确一致性适配。Windows 观察使用 QUERY_VALUE／NOTIFY，不写系统主题，不发终端背景查询，避免应用自己的默认背景反馈进检测。
4. 每个 UI 的 System 阶段仅一个观察器、一个最新待消费观测和一个 Next 读取；关闭完成后才可重建。新选择取消旧阶段，旧打开／读取／关闭回执不覆盖新选择，也不启动并行观察器。观察器随 UI context 结束，无每 Session 进程或后台常驻服务；真实资源成本和 Windows 清理须独立验证。
5. 观测只改变该 Model 的显示 tokens／styles，不写偏好、SQLite 或终端输入，不改变 Session/Run。已有表单输入样式随配色更新，保留文字、光标和焦点。显式 Dark/Light 停止观察，后到结果不能覆盖它们；错误不猜测新主题，也不输出原始检测数据，设置可显式重试。
6. 选择仍在串行偏好保存成功后应用。源 theme_watcher.go 和 dark-mode-go v0.0.2 的 Windows 通知作为固定参考／选择性适配；保留 MIT 通知，不加入该模块依赖。Go 模型／仿真观察器与 Windows 真实注册表／桌面接受分别记录，不绕过上传授权缺口。

## 验证

先验证保存选择、终端声明边界、单阶段生命周期、取消／晚到／重复回执、显式选择优先、错误回退及表单上下文；原生 Windows 使用隔离测试键验证通知和关闭，不能写真实系统主题或以交叉构建替代。完整系统／终端组合、设置面板与发布仍开放。

# ADR-0014：还原上游体验、以 Tab 管理通用终端会话

- 日期：2026-11-22
- 状态：已接受（Accepted），依据用户明确要求更新 ADR 与 Feature Ledger
- 实现与验证状态：首次接受时只确定产品方向；后续 ADR-0015/0016 已接入 psmux Tab、原终端输入、普通 shell 创建与默认 compact 侧栏卡片，并有局部 Windows 证据。完整上游还原、真实 agent、其他后端 Tab 和发布仍未验收，具体范围见本 ADR 后续进展及 Feature Ledger。
- 关联需求：FR-01、FR-02、FR-03、FR-04、FR-05、FR-10、FR-11；关联能力：FL-001/002/003/004/005/006/011/012/018/019
- 部分替代：[ADR-0001](0001-architecture-and-reuse.md) 的最小列表／预览界面约束、[ADR-0002](0002-terminal-backends-and-attach.md) 的默认全屏交接及隐藏 Tab／内嵌交互后置约束；扩展 [ADR-0004](0004-cli-agents-and-session-messaging.md) 的基础管理对象至普通终端

## 背景

当前切片只选择性复用了 Agent Deck 的调色板、布局和列表等基础代码，未保留完整界面体验。用户明确要求：布局、比例、交互、颜色等尽可能还原原项目；Session 以 Tab 页面管理；agent 使用终端自身的输入区，普通命令行终端也属于管理范围。此前将“简约”解释为持续裁减上游界面、将 Tab 隐藏和内嵌交互后置的约束已不符合当前要求。

## 决定

### 上游体验是视觉与交互基线

1. 以已固定的 Agent Deck 源码快照 `80494e527393b7ead00da30018e6ee7e60e9d7a0` 为主要还原基线。布局结构、区域比例、间距、边框、配色、选中／焦点状态、弹窗、键盘与鼠标交互尽可能沿用原有体验，不以仅沿用主题颜色作为完成标准。上游录屏必须核对版本，不能假定历史视频与固定提交完全相同。
2. Tab 主导航和通用终端属于本产品明确要求的适配；其余因 Windows、稳定 Charm v2、通用模型或资源边界产生的必要差异逐项说明来源行为、产品行为、原因和实际验证。未经评审的视觉裁剪不视为已接受；不预先虚构比例数值或复用百分比。
3. 样式继续全部通过 ADR-0008 的 design tokens 管理。保留源码、提交、许可和修改点；上游账户、远程、worktree、成本与编排等业务能力不因视觉还原而自动纳入范围。原 v0.1 图稿仍为未采纳探索。

### Tab 是主要会话工作区

1. 创建、选择、切换和重新打开会话以产品内 Tab 为主要入口。活动 Tab 展示对应终端并可直接操作；输入时保留 Tab 导航及可达的切换入口，无需先 detach 回列表再选择另一会话。列表、分组、搜索可辅助组织，不能代替主 Tab 工作流。具体侧栏布局与比例按上游基线评审，不强制新增一份重复导航。
2. Tab/View、Session、Run 保持不同身份；切换、重命名和排序不创建新 Run，不向终端注入输入。关闭 Tab 仅关闭视图，不停止 Run；重新打开存活 Session 接回原 Run；停止、重启与归档是独立动作，重启生成新 Run。Tab 顺序与标题不作为控制或投递凭据。
3. 现有全屏 attach 可保留为显式进入的辅助模式及后端回归路径。该模式可临时隐藏导航，但不是满足默认 Tab 体验的替代品；已有 attach 证据不等于 Tab 工作区通过。

### Agent 与普通命令行共用终端输入

1. 管理对象包括用户显式选择的交互式 shell、普通 CLI 程序与 agent CLI；沿用 executable/args/cwd/env 和 TOML 模板，普通终端无需 agent 品牌、协议或适配器。默认 shell、启动参数和支持矩阵须在实施时明确并实测，不自动宣称兼容所有 shell。
2. 用户在终端本身的提示符、行编辑或目标程序输入区键入；不在终端外新增一个用于日常输入的统一聊天框，不把任意终端程序包装成结构化聊天。agent 在 shell 内启动时仍使用同一终端输入路径。独立的新建／配置／跨会话发送表单继续按需提供，与终端实时输入分别管理。
3. 普通 shell 中一次命令返回提示符，不结束该 shell 的 Run；在其中启动／退出 agent 也不凭屏幕内容自动推定新的受管理 Run 或 agent 工作状态。根终端进程重启才按既有身份规则新建 Run；agent 生命周期仍需独立证据。未知或不适用的 agent 状态不得显示成 ready/busy、接收或完成。
4. 焦点属于 Tab 导航、管理表单或活动终端之一；方向键、Tab 键、Enter、Ctrl+C、粘贴及 IME 只作用于当前输入消费者。切换不丢失或覆盖子程序维护的未提交输入，不让后台会话收到当前键盘输入。具体管理快捷键先验证冲突，不在本 ADR 固定新键位。

## 保留的架构与实施边界

Go/Charm v2、Windows psmux 3.4.0 候选基线、Unix tmux、终端后台拥有进程生命周期、M0–M2 无强制产品 Host、M3 共享 Host、稳定身份、消息证据与有界资源约束继续有效。本决定不预先选择 Tab 内终端的屏幕模型或传输实现，不自动引入另一套 ConPTY 托管层，也不宣称 psmux 稳定版已经具备所需嵌入能力。实施前须验证屏幕、输入、resize 与后端连接方案；若需改变终端所有权或后端基线，另立 ADR。

FL-018 从“首版之后／后置”改为“首版 M1 单 Tab、M2 多 Tab／计划”。FL-001/002/003/004/012 的现有局部实现保持“实现中”，新增要求列为缺口；任何既有 Windows、资源、IME 和真实 agent 未决门槛均保留。

## 验收与证据

- 同一终端尺寸、字体、主题和合成数据下，对照固定上游版本和当前 Windows 构建，逐项核对布局比例、颜色、间距、选中／焦点、弹窗、键鼠及窄窗口行为；记录全部必要差异、用户评审结论和未通过项。上游截图只能作对照，不能代替本产品运行证据。
- 至少覆盖普通交互 shell、普通 CLI 和真实 agent。shell 执行命令、返回提示符、再运行命令；agent 使用目标程序自己的输入区；两者均无需管理器聊天框。用户当前没有真实 agent，相关验证保留待测，fixture 仅证明它自己的合同。
- A→B→A 的 Tab 切换保留原 Session/Run、终端状态和未提交输入；验证重命名、排序、关闭／重新打开视图、显式停止、退出 TUI 后重连和旧目标拒绝。
- 原生 Windows 验证 IME 组合／取消、多行粘贴、宽字符、颜色／光标、鼠标、alternate screen、resize 与 Ctrl+C；验证管理快捷键与终端键无重复消费、误投或额外提交。
- 为 Tab 路径重新测量当前／后台终端、有界屏幕缓存和 0/1/5/10 会话资源；不复用全屏 attach 的旧数值冒充新路径结果，未定预算保留待判定。人工介入通知继续不抢焦点、不注入输入，后台监测仍需实际消费者。

测试沿用既有 TC ID 更新 JSON 设计与派生文档，仍为 designed/not_run。本次文档核验见[变更报告](../testing/results/2026-11-22-tab-terminal-direction.md)，不产生产品、视觉或 Windows 通过结论。

## 比较与代价

- 继续以列表／预览和全屏 attach 为主：已有局部实现，但不能满足用户明确的 Tab 工作流。
- 增加统一聊天输入框：不能覆盖 shell、全屏 TUI 和目标程序自身的行编辑语义，不采纳为日常终端输入方案。
- 原样 fork 全部上游业务：会扩大与界面还原无关的范围；继续按可追溯源码迁移，但以用户体验还原而非文件复制数验收。

Tab 内完整交互增加终端屏幕模型、焦点、尺寸和资源验证工作。所需技术路径仍待实施验证；本次接受方向不代表已解决这些问题。

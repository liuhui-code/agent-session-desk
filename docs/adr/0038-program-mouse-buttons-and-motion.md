# ADR-0038：程序鼠标按钮、修饰键与有界悬停

- 日期：2026-11-24
- 状态：已接受还原范围内的实施决定；平台行为另验
- 关联：FR-02/03/04/11；FL-002/003/005/012/013/015/016/018/019
- 扩展 ADR-0031 的左键限制；复制选区仍遵循 ADR-0029/0030

## 决定

1. 对最新帧声明 WantsMouse、终端焦点、已连接且非 CopyMode／提示的目标，增加左／中／右单按钮按下、拖动、释放，以及 Shift／Alt／Ctrl 组合。锁定状态不作为鼠标修饰；Meta／Super／Hyper 等未知修饰不猜测。一个 UI 同时只持有一个按钮手势，多按钮和未知状态不构成新手势。
2. 程序事件以独立可选 Mouse 接口及固定 pane-mouse 协议发送；旧 Pointer 接口继续限定原生左键选区。仅旧接口的连接仍只接受既有无修饰左键，不把新事件改写为文字／按键或无修饰左键。正常模式无声明时不转发，CopyMode 不把中／右键和修饰手势当作选择、复制或粘贴。
3. 按钮、最后接受坐标及修饰与原连接代次／内容矩形／屏幕尺寸绑定。匹配释放或无按钮释放只结束原按钮一次；主动键／粘贴／导航／resize 前按最后接受状态释放原 FIFO。不同按钮运动／未知修饰结束原手势，不模拟按钮和弦；外部模式／尺寸变化仍保留释放未知，不向其他模式或新 Run 续接。等待队列继续保留一个释放位置。
4. 无按钮、无修饰且内容内的运动，经原 pane 的 button=35，由固定后台核对是否开启 any-event 跟踪。每 UI 同时最多一个已接受悬停写入和一个最新待发坐标；中间位置合并，不使用定时器或后台采样。按下／主动操作、模式／焦点／几何／代次变化使未发送位置失效；已经接受的事件不假称撤回。
5. 修饰悬停暂不发送：固定后台仅对完整 button=35 单独核对 any-event，不能用 WantsMouse 推定有权限发送含修饰的裸运动。固定窗口注入对 VT／Win32 和旧宿主 record bypass 的按钮位／拖动标志也有源码可见限制；后台修改 pane 焦点只识别完整无修饰 click，既有单 active leaf 帧检查也不是布局变化的锁。本次保留门槛，不借由 Go 协议测试宣称平台兼容。wheel／原生选区和宿主策略不改变。
6. 不新增聊天输入、剪贴板读写、存储／偏好 schema、依赖或视觉值。程序对事件的接受、原生宿主、实体鼠标、真实 agent 及完整体验仍分别验收。

## 验证

逐行为 RED→GREEN：原 pane 三按钮／修饰的精确 wire、非法事件不写、UI 原目标与跨控件夹取、重复／错按钮及未知修饰、主动释放与 FIFO／保留位置、悬停合并／最后坐标和关闭／换视图／外部模式的迟到回执。受控内存流／模型与 Windows 实机分别记账，不绕过尚未答复的上传授权。


2026-11-24 实际程序证据：VT raw stdin的9个普通／Ctrl／Alt按钮组合收到正确序列；Shift三组由Terminal保留，直接无产品对照同样不转发。Win32存在正确事件但全序列有重复／提前释放，严格0/9，原脚本存在性passed不算通过。真实输入、clipboard宿主副作用未知、直接对照和本地单通道候选见[跟进报告](../testing/results/2026-11-24-current-ui-followup.md)与[提议ADR-0040](0040-verified-conpty-single-mouse-channel.md)；未替换远端bundle，所有相关原生／硬件／agent门槛如实保留。

2026-11-25 接续：已接受开发候选 [ADR-0040](0040-verified-conpty-single-mouse-channel.md)取得新目录下 Win32／VT 严格序列与 wheel 单通道实机证据，并接回显式 profile，见[报告](../testing/results/2026-11-25-single-mouse-channel.md)。上段为旧profile历史，严格0/9不改写；默认系统宿主、实体硬件、Shift宿主保留、混合读取器及真实agent门槛保持。

# ADR-0039：新建终端的临时环境覆盖

- 日期：2026-11-24
- 状态：已接受通用终端／UI 还原范围内的实施决定；平台证据另记
- 关联：FR-01/02/03/11；FL-001/002/003/012/013/016/018/019
- 扩展 ADR-0007/0014/0016；不改变只读模板或后台进程所有权

## 决定

1. psmux Tab 的通用新建表单补环境覆盖字段，放在参数之后、创建按钮之前。输入为可空的 JSON 字符串数组，每项为 KEY=value；空白／[] 继承现有环境，不清空父环境。值可为空或包含等号、空格、Unicode，仍沿已有 Launch.Validate 和后端传输守卫；不进行 shell／环境插值。
2. 表单仅构造本次 Launch.Env，保持条目顺序／字面值，重复键、Windows 名称大小写及最终环境由既有 ResolveLaunch／后端合同处理。管理器和用户系统环境不修改，原 Run 不更新环境，新建是明确的单次提交。
3. 字段沿既有 JSON 参数解析、单行粘贴和 64 KiB 字段上限；语法／类型／KEY=value 错误在 Start 前拒绝，不回显环境值。启动请求带有环境覆盖时，后端启动错误不显示原始详情，避免 stderr 回显覆盖值；本项目已知启动错误前缀仅保留程序／工作目录／环境覆盖的静态字段定位，其他原因用通用摘要；已产生 Session／Run 的未知结果仍显示原身份并禁止自动重试。编辑字段中的值由用户查看，不声称密文输入或内存安全擦除。
4. 取消／成功后表单销毁，不把环境写入 UI 偏好、最近目录缓存或 Session 名称／列表；不自动记忆上次值，不保存／修改用户 TOML。模板选择／保存与完整配置编辑器仍是独立缺口；ui.toml v7、SQLite v5、配置 schema v1 和依赖不变。
5. 沿现有通用表单居中、圆角、输入焦点和 token 样式，新增一组标签／输入结构行；窄低屏保持当前字段／光标。源品牌表单没有相同的通用 Env JSON 行，这是通用 executable/args/cwd/env 的产品适配，不冒充原来源逐格一致。

## 验证

逐行为 RED→GREEN：从管理新建入口以键盘／粘贴填写五字段，原字节传入一个 Start；空白继承、空值／等号／Unicode、无效类型／KEY、拒绝与取消不启动、错误摘要不回显环境值、未知结果不重试、关闭重开不记值及长字段／缩放／主题／能力。UI 服务边界、真实子进程环境和 Windows／agent／完整视觉分别记账，保留尚未解决的原生上传门槛。

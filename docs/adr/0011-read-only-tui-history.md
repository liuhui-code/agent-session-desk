# ADR-0011：按需查看只读历史，保持实时控制边界

- 日期：2026-11-22
- 状态：已接受（Accepted），用户授权继续 M1 切片
- 关联：FR-03、FR-10、FR-11、FR-12；FL-003、FL-011、FL-012、FL-013；细化 ADR-0008/0009/0010
- 实现与验证：[历史控制](../../internal/ui/history.go)、[历史视图](../../internal/ui/history_view.go)、[实际报告](../testing/results/2026-11-22-m1-history-ui.md)；完整恢复与发布验收仍待做

## 决定

管理器按 h 打开独立只读历史，按需读取当前作用域最近 100 条元数据。标题明确读取范围；PgUp/PgDown 只在已加载记录中翻页，不宣称覆盖完整历史或实现数据库分页。选择与实时列表分离；Enter 只打开所选 Run 的详情，Esc/h 从详情回历史列表、再回实时列表。历史没有 attach、重启、输入或删除入口。q 仍退出管理器并保留后台。

详情分别显示 Session/Run/backend 身份、入口程序、首次入库时间、停止确认及首次 pane 退出观测的来源和观测时间。当前在线状态、agent 结果和退出码保持未知；记录未出现不表示某件事没有发生。查看历史不探测目标，不把历史行合并为实时会话。CLI history 的 JSON 合同、SQLite schema v2 和启动方式不变。

UI 依赖 session.HistoryRecord 读取模型，经 Manager 转发到 Store；Store.Record 保留兼容别名，UI 不依赖 SQL。实时发现轮询仍可独立更新元数据，历史画面只通过打开或 r 刷新取得快照。当前 TUI 启动仍要求后端初始化／版本探测成功；启动后的后台发现失败不会阻止读取已打开数据库中的历史，CLI history 可在后端缺失时独立使用。

## 有界读取与交互

同时最多一个历史读取请求，5 秒上下文超时；关闭取消、递增代次并丢弃迟到结果。取消尚未返回时重开，等待原请求完成再读取，避免重复并发。退出释放上下文。刷新按 Run ID 保留选择；原 Run 不在结果中则回历史列表。历史读取不随实时列表轮询或窗口缩放自动重复。

详情按终端显示单元格换行，以 ↑↓、Home/End、PgUp/PgDown 滚动；不以截断的 ID 作为控制目标。元数据与错误先经过现有有界文本清洗，去除 ANSI/控制字符后渲染。颜色、间距、标记和布局尺寸继续全部取自 design tokens，不新增主题格式或常驻进程。

## 替代方案与代价

把历史混入在线列表会使 Enter 的含义不清，因此保持独立视图。完整 SQL 分页、历史筛选、归档、终端日志和对话恢复延后；用户可用 CLI history 的 limit 读取最多 1000 条。最近 100 条之外的记录不能从本轮 TUI 访问。

单元／合同测试验证控制边界、迟到结果、取消、刷新、窗口和 token；Windows 原生渲染测试与实际桌面键盘／尺寸检查单独记账，不视为完整 IME、DPI、字体或发布兼容性接受。依赖 API 由 Context7 检索后对照本地锁定的 Bubble Tea 2.1.2 和 x/ansi 0.11.9 源码；未采用文档中的 beta 依赖。

# ADR-0048：独占处理领取、私有凭据与不确定恢复

- 日期：2026-11-26
- 状态：已接受，用户同意推进任务领取与处理归属
- 关联：FR-07/08/09/12/13，FL-008/009/010/013/014/019
- 替代 ADR-0047 的无领取回复与全状态 inbox；保留 Run 委派和回复／投递分离

## 合同

继续使用既有 SQLite 立即写事务、唯一约束和后端 CLI，不增加 Host、网络服务或前端。schema v8 增加 task_claims；v1–v7 事务升级，旧回复仍可离线查询，不为它们伪造领取记录。

增加 claim、renew、claim-status。同一请求最多一条领取记录，独占关联原消息和原 Run。领取者持久保存稳定 claim_id 与独立随机 256-bit 密钥文件；Run 凭据授权目标身份，领取密钥授权该次处理。数据库只保存密钥摘要。公开 ID 和状态查询不能授权续期／回复；同用户文件／数据库控制权的隔离边界沿用 ADR-0047，不声明凭据等同于 PID 身份认证。

私有文件先完整同步并非覆盖发布，后提交领取。首次成功新建且尚未过期时，newly_claimed=true；幂等重试、状态查询和续期始终 false。该标志不落为可恢复的新执行权。响应丢失／进程恢复只能核对旧领取，不能把恢复回执当作再次执行许可；即使仍 active，也不能据此断言此前未执行过。

只领取 queued、无回复且从未结构化领取的请求。inbox 收窄为这类未领取候选，不代表程序 ready，不自行执行。终端投递的 ClaimMessage 与结构化领取共用同库写事务互斥：终端已开始投递的消息不能领取；有任何结构化领取记录的消息也不能再向终端自动粘贴。普通用户直接在终端的输入不在该自动控制面仲裁范围内。

租约默认 300 秒，显式 1–3600 秒；这是工程期限，不是任务执行时长保证。只有私有领取密钥和原 Run 验证均通过、租约仍有效时才能 renew，延长相同期限，不缩短已有截止时间、不授予新执行权。使用持久化 UTC 截止时间，不改变宿主时钟；时钟回拨及未被观察的退出无法获得无依据的精确判断。调用方检查截止时间并按需续期，不能把 active 查询当作无限执行许可。

状态为 active、unknown、replied，与 Message.state 独立。到期或已记录原 Run／pane 退出时，查询／操作可将 active 持久化为 unknown；无后台扫描。unknown 不回 queued、不续期、不替换、不再次授予执行权。它不会强制终止外部工作，也不说明副作用没发生。相同文件重试返回原不确定记录与错误；新文件／新 ID 不能接管。

新 reply 必须提供 --claim-file，核对原 Run、消息、领取密钥与未过期状态；保存回复和封存 replied 在同一事务。旧处理者即使知道公开 ID，也无法在失效后写入新结果。同回复 ID／原正文／原密钥在已保存结果上的重试仅返回原记录；不产生新结果或新执行权。replied 表示保存了一份显式结果，不自动升级为 completed 或用户验收。

## 兼容、边界与证据

这是开发版写接口变更：旧调用方需先领取并新增 --claim-file；旧 v7 结果只承诺保留查询，没有无领取写入兼容旁路。Reply 新增 claim_id；旧结果没有该字段。claim-status MESSAGE_ID 返回原消息与可空 claim，并可持久化到期／退出的不确定状态；离线查询不探测后端。

领取数量受原消息同库 128 条上限、每请求唯一及外键约束，不追加无限尝试历史。私有文件沿用显式路径、完整暂存、同步、硬链接非覆盖发布；数据库备份仅含摘要，调用方另行保护密钥文件。恢复旧备份不证明外部工作未发生，不允许因此重做任务。

现有 UI、原始终端输入、Message 投递状态、Run 生命周期和依赖版本不变。没有自动重新分配、手工 reset／release-to-queue、任务进度或后台消费者。后续若要接管，必须先确定外部副作用与旧执行者如何被可靠隔离，另立合同。

接口和迁移说明见 [AGENT_API.md](../AGENT_API.md)，实际测试及两个独立进程竞争／终止证据见[报告](../testing/results/2026-11-26-task-claims.md)。沿用 Context7 已核验的 SQLite 事务、唯一约束和[复合外键](https://www.sqlite.org/foreignkeys.html)，没有引入可自动重投的通用消息中间件。

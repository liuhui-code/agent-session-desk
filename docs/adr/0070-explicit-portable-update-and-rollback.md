# ADR-0070：按需、同状态格式的便携更新与回退

2026-11-28，用户已同意实施。关联 FL-016／017／018；细化 ADR-0055／0058，公开发行和签名接受另记。

## 本轮合同

采用常见的先下载校验、版本文件并存、切换入口与保留前版模式。仅管理 alpha.json 的 Windows amd64 便携目录，保留现有快捷方式和单实例门禁；不覆盖运行中的 exe，不添加常驻进程、定时检查、自动安装或自动停止 Run。U 继续按需查询，新增 update CLI 提供 download／status／apply／rollback／repair／discard。apply／rollback／repair 须用户明确确认已关闭工作台，仍检查并持有既有启动门禁及 UI 存活 mutex；发现运行中即拒绝，不替用户关闭窗口。

首次升级到支持本协议的程序仍按现有人工交付。后续 apply 要求当前程序和候选都支持 update probe，状态格式与固定终端库相同。首版拒绝跨 SQLite／UI／启动／快捷键／恢复协议格式更新，不用回退旧程序打开新 schema；回退只换程序，保留当前数据，数据库备份供单独核验／人工恢复。不能把恢复备份作为自动撤销新数据的手段。

## 远端与磁盘

- 仅显式 tag 的本仓库公开 GitHub Release；不推定开发构建落后于发布时间。要求 asd-update.json 和 asd-windows-amd64.exe 两个资产均有 API SHA256 digest、uploaded 状态和有界大小。流式下载、双重哈希核对（API digest／合同），仅 HTTPS 和明确 GitHub 资产域重定向；无账号、token、遥测或私人状态。
- 合同声明 platform、源 revision、产品大小／SHA256、全部状态格式与固定终端库哈希。缺少合同的历史包拒绝更新。SHA256／HTTPS 不等于签名或独立发行者认证。
- 一个固定下载槽，最多三份产品版本槽和三份轮转元数据备份；保留当前与前版，准备新版本仅使用第三槽。旧安装目录中原有非本协议文件不自动删。固定事务 intent 在任何安装副作用前发布，中断后不自动重做；status 提示并要求显式 repair。
- 同一 alpha.json 原子替换同时提交入口、文件哈希及前版指针。Windows 文件替换失败可见，不提供删除原清单再写的回退。中断核对只认可 intent 的旧／新清单哈希；外部改动或未知文件保持不动。回退前再次核对前版、当前数据与运行库。并发 CLI／下载由独占 OS 文件锁串行；活动 UI 和更新互斥，不靠进程名猜在线。
- 文件读取和写入限制在已验证根目录；拒绝链接／reparse point、路径越界、大小写别名、未知版本和非法槽。发布用固定独占临时文件和完整关闭后替换／非覆盖发布；不自动轮询清理中断痕迹。

# ADR-0056：有界待办中心与持久稍后提醒

- 日期：2026-11-27
- 状态：已接受；依据用户同意优先实现待办中心／稍后提醒，并要求运行内存不能明显增长
- 实现与验证状态：已实现；[Windows](../testing/results/2026-11-27-attention-center.md)局部验证
- 关联需求：FR-14、FR-11、FR-12
- 关联功能：FL-020、FL-012、FL-015、FL-016
- 补充：ADR-0006、ADR-0049、ADR-0051；不增加后台 Host 或自动投递授权

## 决定

管理模式 t、全局 Alt+A 或点击事项汇总按需打开 Pending items；Alt+N 保持直接定位下一个到期事项。列表提供 All／Due／Snoozed 筛选、来源、类型、摘要与等待／稍后时间。现有来源只支持 approval／question，不凭空生成异常或完成事项。Enter 重新核对原事项／Run 后打开原表单，待办列表不发送答案、批准或 Enter。Esc/q/Ctrl+C 返回原焦点与侧栏状态；打开、返回均排空已接受输入，后续键鼠／粘贴归弹层所有。

s／S 分别稍后 10／30 分钟，u 恢复提醒。稍后仍是 pending、不会标为已查看，继续阻止自动 deliver／新 claim；手动打开只标 viewed。到期等号即 Due，通过现有约 1 秒发现循环／现有桌宠更新恢复展示；不为每条事项添加 timer、goroutine 或进程，不保证 UI 退出后的持续监测。到期不自动打开或回答。来源解决／撤销／Run 结束继续按原合同失效；来源更高版本内容改变时清除旧稍后，相同内容的版本更新保留它。

SQLite v9→v10 在同一事务追加 snoozed_ns 与 reminder_revision；后者独立于来源事件版本，防止旧界面的恢复覆盖新稍后。修改同时复核 scope、事项 ID、事件版本、原 Session/Run/backend/command 和本地提醒修订。只有一项写入在途，提交不确定需关闭刷新后核验，不自动重试。旧版拒绝 v10；离线 check／backup／restore 支持 v1–v10，旧备份仍只在正常打开时升级。

## 资源边界

- 沿用全数据库最多 256 个事项／墓碑、8 KiB detail、16 KiB event 的既有上限，不新增历史副本。
- 待办中心只存选择 ID、筛选与一次写入状态，复用现有快照；只渲染可见行。快照入口再次限制 256 条，缩短时清除尾部引用，关闭时释放弹层状态。
- 不扫描终端历史识别授权，不调用模型，不增加常驻进程或额外轮询。桌宠只呈现到期事项，旧版本点击仍重新核验。
- 工程目标：相同 256 条数据条件下，开启／重复开关弹层的稳态私有内存增量尽量控制在 5 MiB 内。它是本轮验证目标，只有同一真机固定负载实测后才能报告结果；不等同于整产品资源预算或保证值。空数据、256 条数据和弹层本身的成本分别记录，不用 forced GC 制造结果。
- 生产源码每文件含空行／注释不超过 500 行，样式／尺寸均使用 design_tokens.go 或已有 token 组合。

## 取舍与验证

复用现有快照和到期时间字段，比每事项调度器、另一份待办数据库或新服务更易保持资源有界。持久化需要 schema 升级及旧版拒读，不能借旧 JSON 文档悄悄增加会被旧写入者丢弃的字段。

按行为 RED→GREEN 验证持久化／到期、旧修订竞争、内容变化、恢复备份、自动投递继续阻塞、输入排空与失败释放、选择／筛选／鼠标、窄窗、提交不确定及晚到结果。普通／race／vet／模块、原生 Windows 与实际桌面分开；用相同数据在关闭／打开／反复开关弹层间比较私有字节、句柄、线程和采样缺口。完整通知渠道、全局免打扰、真实 Agent 和旧退出问题继续保留各自门槛。
